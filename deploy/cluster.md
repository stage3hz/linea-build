# Несколько серверов с общей базой

Код: `server/src/cluster.js`. Без `CLUSTER_SELF` сервер работает один, как раньше.

## Как это устроено

- На каждом сервере работает «диспетчер». Диспетчеры голосуют и выбирают **главный** сервер. Нужно большинство: 2 из 3 или 3 из 5.
- Главный сервер работает с базой и каждую секунду копирует изменения в хранилище (Litestream → S3).
- Остальные серверы держат живую копию только для чтения, повторяют за главным загруженные файлы и пересылают ему все запросы. Приложение может подключаться к любому серверу.
- Если главный молчит дольше двух «аренд» (по умолчанию 2 × 8 с), выбирается новый главный, при этом номер эпохи растёт. Каждая эпоха пишется в свою папку хранилища, поэтому старый главный не может испортить копию нового.
- Если главный не слышит большинство, он через 8 секунд сам перестаёт принимать запись. Два главных одновременно не пишут.
- Если старый главный вернулся, он становится запасным. Его прежняя база откладывается в файл `linea.sqlite.stale-…` и ни с чем не смешивается.
- На время переключения (10–25 с) короткие запросы ждут на сервере. Приложение само повторяет неотправленные сообщения, а сервер отбрасывает дубли по `clientId`.

## Честные ограничения

- Копирование асинхронное (1 с). Если главный сервер **внезапно умрёт**, могут потеряться изменения последних ~1–2 секунд, в том числе уже подтверждённые.
- Нужно **нечётное число серверов, минимум 3**. Если работают 2 из 3, всё работает. Если остался 1 из 3, сервер отвечает только на чтение и пишет 503, а новый главный не выбирается. Это сделано намеренно, против раздвоения базы.
- Хранилище S3 должно быть доступно всем серверам. Лучше всего — в отдельном дата-центре, например Timeweb S3.
- Большие файлы появляются на запасных серверах с задержкой до нескольких секунд.

## Установка (на каждом сервере)

1. Общий токен (одинаковый на всех): `openssl rand -hex 32`.
2. В `deploy/.env` каждого сервера (пример для `msk`):

```
CLUSTER_SELF=msk
CLUSTER_SELF_URL=https://api.invizent.com
CLUSTER_PEERS=[{"id":"spb","url":"https://api2.invizent.com"},{"id":"nsk","url":"https://api3.invizent.ru"}]
CLUSTER_TOKEN=<токен из шага 1>
CLUSTER_REPLICA=s3://<бакет>/invizent
CLUSTER_S3_ENDPOINT=<адрес S3 из панели провайдера>
CLUSTER_S3_REGION=<регион из панели>
LITESTREAM_ACCESS_KEY_ID=<ключ S3>
LITESTREAM_SECRET_ACCESS_KEY=<секрет S3>
```

3. Только на сервере, где уже лежат данные, и только при **первом** запуске добавь `CLUSTER_BOOTSTRAP=1`. После запуска эту строку убери.
4. Запуск: `docker compose -f deploy/compose.production.yml up -d --build api`.
5. Проверка: `curl https://api.invizent.com/health` показывает `"role":"leader"` или `"follower"`.

Ключи S3 и токен держи только в `.env` на серверах, не в git и не в чате.
Endpoint и регион S3 бери из панели своего провайдера.
