# Линия: сервер и приложение с одного iPhone

Задача: управлять сервером с iPhone и установить на этот же телефон отдельное iOS-приложение. Для этого сервер работает на Linux VPS, команды запускаются через SSH с телефона, а iOS-приложение собирается на облачном Mac в EAS Build. Собственный Mac для этого маршрута не требуется. [Как EAS собирает iOS](https://docs.expo.dev/build-reference/ios-builds/).

**Этот комплект не содержит готового IPA или сертификатов.** Он подготавливает копию исходников к первой облачной сборке. Успешная генерация конфигурации и проекта Xcode без установки Pods не подтверждает успешную компиляцию Swift, подпись или запуск на устройстве. Реальные результаты находятся в `PREPARATION_REPORT.md` и `VERIFICATION.json`.

Если под сервером «на iOS» подразумевается постоянный сервер внутри самого iPhone, такой режим в Линии не реализован. Текущий сервер использует Node.js 24, Docker и SQLite. Обычные приложения iOS могут быть приостановлены после ухода в фон; дополнительное время выполнения ограничено системой. [Правила фонового выполнения Apple](https://developer.apple.com/documentation/uikit/extending-your-app-s-background-execution-time).

## Что потребуется

- Новый VPS и HTTPS-адрес API; порядок размещения находится в `docs/DEPLOY_FROM_IPHONE.md` полного проекта.
- Полный исходный архив Линии. Небольшой `linea-server-*.zip` не содержит мобильного клиента.
- Учётная запись Expo и реальный проект EAS для этого приложения.
- Право использовать действующие Apple signing credentials: сертификат с закрытым ключом и профиль ad hoc для нужного bundle ID и iPhone. Их можно создать через свою Apple Developer Team либо использовать уже подготовленные владельцем этой Team. Одного включённого Developer Mode недостаточно. [Учётные записи и готовые credentials](https://docs.expo.dev/app-signing/apple-developer-program-roles-and-permissions/).

Для ad hoc установки устройство должно находиться в профиле. Регистрация устройства в Expo сама по себе не дописывает его в чужой готовый файл `.mobileprovision`. Если права обновить профиль отсутствуют, нужен уже подходящий профиль от его владельца. [Internal distribution](https://docs.expo.dev/build/internal-distribution/).

В этой сессии ни действующий профиль, ни содержимое упомянутого архива Premium не проверены. Я не могу подтвердить их пригодность без самого файла и проверки.

## 1. Поднять API с iPhone

В Safari создайте VPS, через SSH/SFTP загрузите серверный комплект и выполните его инструкцию. Для `/opt/linea` основной запуск после заполнения собственных доменов:

```bash
cd /opt/linea
docker compose --env-file deploy/.env -f deploy/compose.production.yml up -d --build
```

Сначала проверяется `https://ВАШ-ДОМЕН/health`. Затем, после установки приложения, проверяется настоящий обмен сообщениями между двумя аккаунтами. Проверка health не является проверкой E2EE.

## 2. Подготовить отдельную копию мобильных исходников

Следующие команды выполняются по SSH на VPS с уже установленным Docker. Используйте новый каталог, отдельный от рабочего API и его данных. Загрузите полный исходный архив и этот комплект через SFTP в `/root`.

Для исходного архива 0.5.1:

```bash
apt update
apt install -y unzip
mkdir -p /opt/linea-ios
unzip /root/linea-messenger-v0.5.1.zip -d /opt/linea-ios
```

В полном исходном архиве есть верхний каталог `linea-messenger`. После распаковки мобильный клиент должен находиться в `/opt/linea-ios/linea-messenger/mobile`. Комплект подготовки в версии 0.5.1 включён в `tools/ios-cloud-setup/`.

Для команд EAS можно использовать отдельный контейнер Node.js, сохраняя служебное окружение между подключениями:

```bash
docker run --rm -it \
  --mount type=bind,src=/opt/linea-ios/linea-messenger,dst=/work \
  --mount type=volume,src=linea-eas-home,dst=/root \
  --workdir /work/mobile \
  node:24-bookworm bash
```

Каталог `/work` внутри контейнера — только отдельная копия исходников. Рабочая база API и его реальные настройки в этот контейнер не подключаются. `node:24-bookworm` основан на официальном buildpack-deps и содержит Bash/Git. [Node Dockerfile](https://github.com/nodejs/docker-node/blob/main/24/bookworm/Dockerfile), [buildpack-deps](https://github.com/docker-library/buildpack-deps/blob/master/debian/bookworm/scm/Dockerfile).

## 3. Привязать исходники к своему Expo-проекту

Внутри контейнера:

```bash
cd /work
printf '\ncredentials.json\n*.p8\n*.pfx\n*.pem\n*.key\nsigning/\n' >> .gitignore
git init -b main
git config --local user.name 'Linea build'
git config --local user.email 'build@localhost'
git add .
git commit -m 'Prepare local EAS build'
cd /work/mobile
npm ci
npx --yes eas-cli@latest login
npx --yes eas-cli@latest init
```

Git создаётся в `/work`, где находится общий `.gitignore`, а EAS запускается в `/work/mobile`. Имя `Linea build` и адрес `build@localhost` — служебная подпись локального коммита, а не данные входа. GitHub и отправка кода в Git-репозиторий не нужны. EAS использует Git при подготовке загружаемых файлов. [Project upload process](https://docs.expo.dev/build-reference/project-upload/).

Наш `app.config.js` динамический. Если EAS создаст проект, но попросит добавить `extra.eas.projectId` вручную, возьмите настоящий Project ID из вывода CLI или настроек созданного проекта. Не подставляйте выдуманный UUID. Для подготовки и привязки используется:

```bash
node /work/tools/ios-cloud-setup/prepare-ios.mjs /work/mobile \
  --app-version 0.5.1 \
  --project-id ВАШ_НАСТОЯЩИЙ_PROJECT_ID \
  --owner ВАШ_EXPO_OWNER \
  --bundle-id ВАШ_ЗАРЕГИСТРИРОВАННЫЙ_BUNDLE_ID
```

**Замените все три значения перед запуском.** `owner` — имя пользователя или организации Expo, а bundle ID должен соответствовать вашему Apple-профилю. Эти поля публичные; пароли в аргументы не передаются. Необязательные параметры можно пропустить и добавить позднее. В текущем исходном проекте preview ID — `com.linea.messenger.preview`; его доступность для вашей Apple Team не проверена.

Подготовщик проверяет известный исходный конфиг, хранит его резервную копию, включает статические iOS frameworks для LibSignal и добавляет защитные настройки геолокации/изоляции. Повторный запуск сохраняет уже заданные публичные параметры; чужие изменения управляемого конфига не перезаписываются. `eas.json` не заменяется.

После привязки проверьте проект:

```bash
npx --yes eas-cli@latest project:info
```

## 4. Настроить подпись и зарегистрировать телефон

Для своей Apple Developer Team:

```bash
npx --yes eas-cli@latest device:create
```

Выберите регистрацию через Website и откройте полученную ссылку в Safari на том iPhone, куда будет установлено приложение. Следуйте системному процессу регистрации. Для уже подготовленных credentials используйте `eas credentials` и документированный порядок их синхронизации. Пароль `.p12`, если нужен, вводится в своём защищённом процессе настройки. [Синхронизация credentials](https://docs.expo.dev/app-signing/syncing-credentials/).

Не переносите `credentials.json` или файлы сертификатов в публичный репозиторий. В стандартном профиле используются credentials, управляемые EAS. Если появится `.easignore`, он заменит правила `.gitignore`; защитные исключения нужно сохранить. [Правила .easignore](https://docs.expo.dev/build-reference/easignore/).

## 5. Собрать и установить отдельное приложение

```bash
npx --yes eas-cli@latest build --platform ios --profile preview
```

Профиль `preview` задаёт `distribution: internal`, не включает development client и не является сборкой симулятора. Ожидается отдельное приложение со встроенным JavaScript, которому не нужен постоянно работающий Metro. `APP_ENV=development` в этом проекте выбирает preview-идентификатор; это не обещание dev-runtime. [Смысл профилей EAS](https://docs.expo.dev/eas/json/).

После успешной сборки откройте страницу установки EAS в Safari на своём iPhone. Для ad hoc работает только устройство, разрешённое профилем подписи. Если сборка завершается ошибкой Pods/Swift/signing, её нужно исправить по реальному журналу; данный комплект не подтверждает, что эти этапы уже прошли.

Если режим разработчика ещё не включён, после установки откройте приложение и следуйте запросу системы: **Настройки → Конфиденциальность и безопасность → Режим разработчика**. Включите его, перезапустите iPhone и подтвердите включение после перезапуска. Этот шаг выполняется на самом iPhone; при уже включённом режиме повторять его не нужно. [Официальная инструкция Expo](https://docs.expo.dev/guides/ios-developer-mode/).

При первом запуске укажите свой HTTPS-адрес сервера. Пустой адрес в preview-конфигурации допускает ввод на экране подключения. Секретные серверные ключи не вводятся в `EXPO_PUBLIC_*`. Отдельно настраиваются реальные сервер и DNS; наличие ссылки установки не проверяет сервер.

## 6. Геолокация, изоляция и Platina

Приложение не должно определять местоположение. Защита конфигурации запрещает location permissions, iOS location usage descriptions и фоновый режим location. Системная песочница iOS отделяет приватные файлы приложения; прямое совместное хранилище и общие keychain-группы не включаются. Выбор файлов, копирование и меню отправки доступны только через явные действия пользователя. [Песочница iOS](https://support.apple.com/guide/security/security-of-runtime-process-sec15bfe098e/web).

Это не утверждение, что любой произвольный PDF/ZIP/аудиофайл не содержит координат, написанных внутри него. Поддерживаемые фото/видео очищаются штатным клиентом; обычные документы передаются как выбранные пользователем файлы. Серверу нужен сетевой IP для соединения и защиты входа; прикладного определения местоположения по IP в проверенном коде нет. Подробные границы проверки находятся в документах версии 0.5.1.

Бессрочную Platina владелец сервера выдаёт отдельной доверенной командой после создания аккаунта. Username нужен для поиска, выдача закрепляется за UUID. Это право на возможности Platina; оно не добавляет мобильному приложению системных привилегий. Команды и результаты тестов: `docs/PLATINA_OWNER_0.5.1.md` полного проекта.
