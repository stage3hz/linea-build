# Профиль, статусы и три оформления — 0.5

## Фактическое поведение

В профиле раздельно показаны неизменяемый логин для входа, стабильный ID аккаунта и публичное имя `@username`. Логин и ID можно скопировать, но нельзя редактировать. Публичное имя имеет отдельное поле; перед изменением открывается подтверждение с прежним и новым именем, неизменяемым логином и указанием, будет ли использована единственная бесплатная смена. Клиент не подменяет неизвестный логин текущим публичным именем: поле появляется после ответа сервера.

Права и состояние запрашиваются через `Api.usernameStatus()`. Изменение имени использует `changeUsername(username)`, статуса — `changeStatusEmoji(statusEmoji)`. Формат публичного имени проверяется до подтверждения: 3–24 символа `a-z`, `0-9`, `_`; ведущий `@`, внешние пробелы и регистр нормализуются. Право смены и свободность имени окончательно проверяет сервер. При сетевой ошибке интерфейс обновляет состояние прав, не объявляет смену успешной и оставляет пользовательский ввод.

`Platina` показана только в собственном профиле. Доступны справка о возможностях этой версии и библиотека 12 статичных Unicode-эмодзи. Выбор или замена доступны по серверному `canSetStatusEmoji`; очистка статуса доступна и без активного права. Нет кнопки покупки, локальной активации или обещания работающих анимированных наборов. Справка прямо указывает, что анимированные статусы/аватары и оформление каналов ещё не поддерживаются.

В списке чатов, заголовке диалога и карточке собеседника показывается только выбранный эмодзи рядом с именем. Общий [`StatusEmoji`](../mobile/src/StatusEmoji.tsx) получает публичного пользователя; по умолчанию ничего не выводит. Разрешены только известные статичные эмодзи с конечным будущим `statusEmojiExpiresAt`. Отсутствующий, пустой, некорректный или истёкший срок скрывает статус. Таймер и событие возврата приложения в активное состояние повторяют проверку. Клиент не выдаёт серверное право по локальному времени; это только скрытие устаревшего публичного статуса. Срок показа зависит от часов устройства; сервер повторно проверяет entitlement при изменениях.

Операции профиля сериализуются локальным блокиратором. Результат применяется только в актуальном API/аккаунте и поколении экрана. Закрытие или смена аккаунта делает поздний ответ неактуальным. В `App` callback обновления пользователя дополнительно проверяет токен текущей сессии и ID, чтобы старый ответ не заменил пользователя другой сессии. Это не отменяет уже выполненную серверную мутацию; при следующем открытии профиль перечитывается с сервера.

Выбор аватара использует `allowsEditing:false`, `quality:1`, `Current` на iOS. Встроенная обрезка picker не применяется перед инспекцией оригинала. Общий `Api.upload` владельца media pipeline выполняет очистку, а UI проверяет фактический итоговый размер до 4 МиБ. Интерфейс не обещает сохранение HDR-аватара: неподдерживаемый HDR отклоняется без скрытого перевода в SDR. Внешний вид аватара обрезается только рамкой отображения. Анимированные аватары не реализованы.

## Векторная надпись Platina

После получения двух референсов подключён [`PlatinaWordmark`](../mobile/src/PlatinaWordmark.tsx): в заголовке карточки [`ProfileScreen`](../mobile/src/ProfileScreen.tsx) он заменяет прежнюю текстовую надпись. Компонент использует готовые прозрачные SVG [`platina-chrome.svg`](../mobile/assets/branding/platina-chrome.svg) для обеих тёмных палитр и [`platina-chrome-light.svg`](../mobile/assets/branding/platina-chrome-light.svg) для светлой; выбор следует фактическому `t.dark`. В чатах, списках и карточках собеседников эта надпись не добавлена.

Оба файла имеют `viewBox="0 0 1600 520"`; проверка XML показала векторные контуры, градиенты, окружности и clipping, без встроенных растров, текста с внешним шрифтом или SVG-фильтров. Загрузка выполняется через локальный `require()` и уже установленный `expo-image`, без новых зависимостей и без цветового `tint`, который изменил бы хром. Поддержка SVG и локальных ресурсов описана в [Expo Image SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/image/); также проверены установленный SVG decoder Android, SVG coder iOS и наличие `svg` в Metro `assetExts`.

В интерфейсе сохранена пропорция `1600 / 520`: ширина до 220 логических пикселей соответствует высоте 71,5. В более узкой строке надпись пропорционально уменьшается внутри `flex:1, minWidth:0`, а статус справа сохраняет место и может переноситься в пределах 45% строки. Изображение имеет доступное имя `Platina` и роль `image`. Это описание реализованных ограничений layout; визуальная проверка компонента на Android/iPhone не выполнена.

## Оформление и сохранение

В [`theme.tsx`](../mobile/src/theme.tsx) три палитры:

| Выбор | Поведение |
|---|---|
| Светлая | Существующая светлая палитра. Ручной выбор не зависит от ОС. |
| Тёмная | Существующая тёмная синяя палитра сохранена; базовый фон `#080F1E`. |
| Чёрная | Базовый фон и непрозрачный материал `#000000`; прозрачные чёрные панели, нейтральные блики и границы. |
| Автоматически | Следует светлой/тёмной теме ОС. Для тёмной системы отдельно выбирается прежняя тёмная или чёрная палитра. |

На первом запуске активен `system`; тёмный вариант по умолчанию — прежний `dark`. При `light`, `dark` или `black` изменения ОС не меняют выбранную палитру. Неопределённая системная тема (`null`, `unspecified`) при автоматическом режиме использует светлую. Переключение на ручную тему выключает автоматический режим; включение автоматики возвращает следование системе.

`ThemeMode` хранится под прежним ключом `linea.theme.v1`, а выбор тёмной системной палитры — под новым `linea.dark-theme.v1`. Чтение принимает `black`, старые значения сохраняют своё поведение. Записи выполняются последовательно, чтобы поздно завершившийся старый выбор не перезаписал новый. Ошибка сохранения видна пользователю и не блокирует последующие попытки. Настройки доступны в профиле и до авторизации через общий [`ThemeSettings`](../mobile/src/ThemeSettings.tsx).

Для чёрной палитры добавлены нейтральные ветки в материалах стекла, подложке панели вложений, датах и границах сообщений, выделении строки чата. Системное уменьшение прозрачности продолжает использовать непрозрачную палитру. В `App` рядом с очисткой фото-кэша добавлен вызов `clearVideoCache()` при старте; недоступность нативного модуля в веб не включает обходной путь загрузки оригиналов.

## Предпросмотр и оставшееся ограничение

Подготовлен отдельный рабочий web harness в `media-update/ui-preview` и Expo-export в `media-update/ui-export` (вне исходного проекта). Он импортирует текущие компоненты без копирования UI, использует явно тестовый профиль и отключает сетевые AI/загрузки. Предусмотрены профиль в трёх темах, общие настройки оформления, AI без подключённого ключа, настоящие веб-состояния недоступности галереи и редактора. Галерея не подменена фиктивной сеткой; обработка фото не имитируется. Экспорт завершился успешно, **455 модулей**.

**Визуальная проверка и скриншоты не завершены.** Встроенный браузер отклонил локальный URL `http://terminal.local:4174/review.html` сначала с `ERR_BLOCKED_BY_CLIENT`, затем явно сообщил об отказе своей URL security policy и запретил обход через иной механизм браузера. Попытки остановлены. Локальный тестовый сервер был запущен после автоматического разрешения, однако разрешение процесса не снимает отдельную политику браузера. Снимков нет; качество отображения на реальном телефоне или в браузере этим отчётом не подтверждается.

Для повторения разрешённой локальной проверки: из `media-update/ui-preview` запустить `node node_modules/expo/bin/cli export --platform web --output-dir ../ui-export`, скопировать соседний `review.html` в `../ui-export`, затем `node server.mjs`. Страница `/review.html` показывает iframe шириной 390 CSS-пикселей для проверки компоновки; нативные материалы, клавиатура, разрешения и обработка медиа требуют Android/iPhone.
