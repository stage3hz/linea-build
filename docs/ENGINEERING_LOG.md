# Журнал разработки — версия 0.3.0

## Правила работы

2026-10-28 пользователь передал архив `ub-mode-master.zip` и попросил применять его к приложению. Архив содержит только README и SKILL; исполняемого кода, интерфейсной библиотеки или лицензированного музыкального каталога в нём нет. Полный SKILL прочитан. Правила применяются к дальнейшим изменениям; более ранняя работа не объявляется задним числом выполненной строго по TDD.

Принятые правила: согласованные модели данных до интеграции; проверка входных данных на границах; один владелец изменяемого состояния; небольшие изменения с проверяемым результатом; воспроизведение дефекта до исправления; тесты наблюдаемого поведения; атомарность и повторяемость операций после сбоя. Результаты Crapper/Dryer/Mutator фиксируются только после фактического запуска и с указанием поддержанного языка/области.

Git remote в проекте не предоставлен. Отправка изменений в чужую или придуманную основную ветку не выполняется. Результат передаётся исходниками и доступной сборкой. Файлы действующих сборок, ключей и проверок не удаляются ради очистки диска.

## Глоссарий

- **Пароль** — секрет входа в аккаунт. Сервер хранит его salted scrypt-хеш.
- **Слово входа** — дополнительный секрет знания для обычной авторизации; это не независимый второй фактор.
- **Слово восстановления** — отдельный секрет для запуска восстановления пароля с задержкой.
- **Recovery grant** — короткоживущее одноразовое разрешение на смену пароля; не токен обычной сессии.
- **Сессия аккаунта** — авторизованный HTTP/WS доступ с возможностью отзыва.
- **Устройство шифрования** — локальная идентичность с приватными ключами, которых сервер не получает.
- **Код безопасности** — отпечаток пары публичных ключей для сравнения по доверенному каналу; не секретный ключ.
- **Одноразовый prekey** — заранее опубликованный публичный ключ для открытия асинхронной Signal-сессии.
- **Ratchet state** — приватное состояние обновления ключей Signal Protocol на клиенте.
- **Outbox** — атомарно сохранённый шифротекст отправляемого сообщения для точного повторного запроса.
- **Inbox cursor** — позиция последнего проверенного пакета в последовательной обработке конкретного чата.
- **SQLCipher vault** — зашифрованное локальное хранилище ключей и расшифрованной истории.

## Ограничения утверждений

### Итерация 0.4.0: фото перед отправкой

Источник требований — новое сообщение пользователя: функциональное соответствие Telegram и встроенная обработка фото. Подготовлена матрица 34 групп функций Telegram с официальными источниками; архитектура Linea не заменялась на TDLib, а отсутствующие функции не объявлялись реализованными.

Для фото создан отдельный native module Android/Swift. Операции выполняются локально; PNG декодируется/кодируется заново в sRGB, затем очищается строгим allowlist. Увеличение обозначено как bicubic, inpainting — заполнение небольших областей, не генеративная модель. Операции сериализованы; размеры, маска, входные URI и память ограничены. Уменьшение требует явного выбора, в том числе если PNG не помещается в 20 МиБ.

PNG-функции начинались с 20 ожидаемых RED из 21 на отсутствии реализации; native pixel core — с 6 RED; pipeline — с 11 RED; настоящий upload caller — с 3 RED из 4. Реализация довела проверки до GREEN. Независимый review закрепил regression-first неправильный порядок PLTE/tRNS и ложное распознавание текста с `BM` как фото. Исправлены ошибки строгого TypeScript без ослабления конфигурации. Взаимный review исправил native cleanup при ошибке чтения атрибутов PNG на iOS и неудачном удалении oversized PNG на Android.

UI сохраняет исходник и результат, запрещает отправку устаревшего preview, держит временный PNG до окончания upload и игнорирует результат picker для прежнего аккаунта/чата. Подготовка перенесена также непосредственно в `encryptAndUpload`; фото из файлов и распознанные по байтам изображения не отправляют исходник в обход очистки. Имя выхода — `photo.png`, размер вложения считается по фактически очищенным байтам.

Итог: 107 photo checks, 27 E2EE checks, 10 native photo JVM checks, TypeScript и export all прошли. Первый E2EE replay был 26/27 из-за Java17 в PATH; повтор с JDK21 дал 27/27 без изменения кода. PNG scope: 16 функций CRAP<10, максимум8; Dryer0; Mutator113/113. Метрики остальных TSX/Kotlin/Swift не выдаются за полностью пройденный quality gate. Исторические0.3 evidence сохранены отдельным срезом. Полная APK-проверка и manifest текущих78 production inputs — PHOTO_BUILD_REPORT.

Зависимости JS/сервера не менялись; добавлены native Android ExifInterface/ML Kit/Google Play base и системные Apple frameworks. Git repository/remote по-прежнему отсутствуют; commit/push не заявляются. Исходники, отчёты и APK сохраняются как версия0.4.0 после проверки упаковки.

Успешные тесты не являются независимым аудитом безопасности и не доказывают абсолютную неуязвимость. Доставка push при полностью закрытом приложении, перенос старой истории на новый телефон и полноценная браузерная E2EE-версия в этой реализации не заявляются. Развёртывание на реальных .ru/.com не состоялось без доменов и VPS. Точные результаты нативной сборки и доступные артефакты отражаются в итоговом TEST_REPORT.
