## Авторизация и восстановление

Полные сценарии описаны в `AUTH_TEST_REPORT.md`. Реализованы четыре парных шага регистрации; вход ник → пароль → отдельное подтверждение без предварительной проверки ника; независимое восстановление по recoveryWord; три неверных попытки/24 часа; серверное ожидание 10 минут; одноразовый grant ещё на 20 минут; отмена старым сеансом; отзыв всех сеансов после смены credentials.

Проверялись гонки регистрации/восстановления/отзыва, истечение и повтор grants, изоляция аккаунтов, неизвестные ники, сохранность счётчиков после рестарта, legacy Unicode/password migration, WS и HTTP-сессии. Native keyboard/autofill на реальных Android/iPhone не испытаны. Односимвольную вставку невозможно надёжно отличить от нажатия клавиши по одному text-change событию; это явно зафиксировано тестом и не выдаётся за абсолютный запрет всех способов ввода.

Дополнительно воспроизведены и исправлены: возможность повторно зарегистрировать отозванное устройство с прежним auth token; порядок создания unique session index при schema migration; null вместо attachmentIds array; новый пароль только из пробелов. Финальный полный прогон включает проверки этих границ.

## Сквозное шифрование

`E2EE_TEST_REPORT.md` и `NATIVE_TEST_REPORT.md` разделяют real SDK, настоящий Kotlin core и ещё не проверенный физический runtime.

Проверены handshake, двусторонний ratchet, out-of-order, replay, повреждение ciphertext, подмена identity/prekey, потеря ключей, explicit trust gate, пополнение prekeys, атомарный outbox/state/cache commit, идентичный повтор после ошибки, контекст chat/sender/recipient/device, ciphertext-file upload/download и восстановление аккаунта при сохранённом локальном vault. Использованы official libsignal 0.106.0 и настоящий Fastify API с временной SQLite.

Два конкретных дефекта закреплялись до исправления:

- Sync random API мог использовать слабый fallback при отсутствии native RNG. Два теста реальных callers сначала падали, после перехода на async CSPRNG стали проходить; ключ и upload при отказе RNG не создаются.
- Некорректная форма encrypted envelope могла уронить preview через `.some`. Добавлена единая проверка внешней структуры; неверный пакет отображается как invalid и не продвигает ratchet/cursor.

Пароль/слова не являются encryption key. Новое устройство не читает прежнюю историю без прежних приватных ключей. Сервер видит метаданные доставки. Старый plaintext не зашифрован задним числом и скрыт production API. Web и Expo Go не получают небезопасного plaintext fallback.

## Визуальная проверка и скриншоты

Проверены текущие React Native компоненты в web-представлении: чаты, поиск людей, музыка, профиль, открытый диалог, безопасность, вход и нижние настройки профиля. Сняты светлая/тёмная темы; на скриншотах указано, что контакты, сообщения, устройства и треки тестовые. Отдельный UI harness не входит в production entry point и не подменяет реальную авторизацию приложения.

Это проверка вида компонентов в браузере, а не установка Android/iPhone-приложения. Native glass, системная клавиатура, picker, Keychain/Keystore, SQLCipher на устройстве, звонковые прерывания и работа музыки в фоне требуют отдельного испытания. Исторические музыкальные проверки v0.2 описаны в MUSIC_TEST_REPORT; в v0.3 повторены 11 проверок каталога, но не заявляется новое испытание физического аудио.

## Зависимости

`npm audit --json`: сервер — **0** известных замечаний; mobile dependency tree — **8** затронутых записей: **3 high +5 low**. Это не восемь независимо найденных дефектов приложения.

- Zod `<4.6.6`, [GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5): high, чрезмерная память при валидации больших ограниченных коллекций. Цепочка Expo CLI → Zod.
- deepmerge `>=4.2.0 <=4.3.1`, [GHSA-gcqx-w48m-w2h4](https://github.com/advisories/GHSA-gcqx-w48m-w2h4): low по npm, prototype poisoning результата mergeObject. Цепочка конфигурационных/build инструментов Expo.

Исходники runtime приложения не импортируют Zod/deepmerge напрямую. Эксплуатируемость в этом проекте не установлена. Автоматический audit fix, предлагающий понизить Expo SDK с 57 до 51, не применялся. Эти предупреждения остаются открытыми; отчёт не объявляет дерево зависимостей полностью безопасным.

## ub-mode

Присланный SKILL прочитан и применён к последующим изменениям. Не утверждается, что ранняя работа задним числом выполнена строго по TDD. Причины изменений и проверки записаны в ENGINEERING_LOG. Реальные версии/scope/результаты Crapper, Dryer и Mutator — в QUALITY_REPORT. Выполненные инструменты не означают автоматически достижение всех порогов для JS/TS/Kotlin/Swift; непроверенные языки и оставшиеся метрики должны оставаться явно отмеченными.

## Ограничения передачи

Нет независимого аудита, нагрузочного теста, реального .ru/.com TLS deployment, восстановления backup на VPS, APNS/FCM для закрытого клиента, переноса клиентской истории или подписанного iOS IPA. Приложение не является функциональным клоном Telegram 1:1. Подпись Android preview не является ключом владельца для публичного выпуска. Результаты компиляции/JVM не заменяют реальный обмен сообщениями на двух телефонах.
