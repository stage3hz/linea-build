## Воспроизведение

Из корня проекта после установки зависимостей:

```bash
cd server
npm ci
npm test
```

Штатная команда в `server/package.json` — `npm test`; она запускает тот же Node Test Runner для файлов `test/*.test.js`.

Проверка выполнена в Linux с **Node.js v24.22.1**, **npm 11.9.0**, встроенным модулем `node:sqlite` и установленными зависимостями сервера: Fastify **5.12.7**, `@fastify/websocket` **11.3.4**, `@fastify/multipart` **9.4.0**, `ws` **8.22.0**. Версии записаны в `server/package.json` и зафиксированы в `server/package-lock.json`.

Каждый сценарий создаёт отдельный временный каталог базы и файлов. HTTP-запросы идут через Fastify `inject` в тот же обработчик приложения. WebSocket-сценарии поднимают настоящий сервер на `127.0.0.1` с автоматически выбранным свободным портом и подключаются библиотекой `ws`. Внешний сервер не используется. После тестов соединения закрываются, временные данные удаляются.

Ограниченная среда изначально запрещала слушать localhost (`EPERM`). Итоговый прогон выполнен с разрешённым локальным сокетом. В нём нет отключённых или подменённых WebSocket-проверок.

## Музыка: фактически выполненные проверки

Итоговый `npm run check` завершился с кодом 0: **16/16** серверных тестов, **11/11** тестов музыкальных разрешений и пагинации, TypeScript без ошибок. Время музыкального набора — 114,6 мс. Независимые тесты находятся в `mobile/test/music-catalog.test.mjs`; границы проверки перечислены в `MUSIC_TEST_REPORT.md`.

Через настоящий web-экспорт React Native клиента в браузере, в области 390 × 812:

- Раздел «Музыка» открыт с экрана входа без регистрации и без пользовательского токена.
- Начальная выдача загружена с Audius. Поиск `Skrillex` вернул публичные треки и ремиксы с разрешённым скачиванием. Настроение «Спокойно» изменило выдачу и вернуло семь подходящих записей на первой проверенной странице.
- Трек `More Than Enough` / Alina Baraz воспроизводился через реальный адрес источника. Видимый таймер изменился с **0:16 до 0:22**, после чего нажата пауза; показана длительность **2:31**. Это проверка состояния браузерного воспроизведения, а не подтверждение звука на телефоне.
- Добавление в «Любимое», открытие очереди и расширенного плеера сработали. После перезагрузки страницы на финальном web-экспорте избранный трек восстановился по сохранённому ID. Мини-плеер оставался доступным при переходе между экранами. Светлый и тёмный музыкальные экраны просмотрены при ширине 390 px.
- Кнопка «Скачать через Audius» завершила повторную проверку и открыла отдельное окно загрузки без ошибки интерфейса. Завершение записи файла браузером на устройство этой UI-проверкой не подтверждено. Официальный download endpoint отдельно ответил **206 audio/mpeg** на Range-запрос одного байта; полный файл приложением не сохранялся.

Статический обзор выявил и устранил два дефекта до финальной сборки: `File.move()` меняет URI объекта, поэтому временный объект больше не удаляется после успешного переноса; восстановление избранного теперь публикуется через общую очередь сериализации, чтобы параллельная запись индекса не затирала метаданные в памяти.

Сохранение своих файлов на Android/iOS, picker, восстановление библиотеки после перезапуска нативного приложения, проигрывание в фоне, экран блокировки, прерывания звонками и подключение Bluetooth **на устройстве не проверялись**. Конфигурация и код этих возможностей присутствуют; это не заменяет испытание.

### Материалы стекла: что именно реализовано

`mobile/src/glass.tsx` использует нативный iOS GlassEffect только при доступности API/компонента; на iOS 26+ эта возможность предусмотрена [Expo GlassEffect SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/glass-effect/). Системное уменьшение прозрачности и изменение этой настройки обрабатываются отдельно; вместо прозрачных материалов используется плотная заливка. На web учитывается поддерживаемый браузером `prefers-reduced-transparency`.

Android применяет `dimezisBlurViewSdk31Plus`: нативный blur начиная с Android 12 и fallback без blur на более ранних версиях. Общий `BlurTargetView` содержит **только декоративный фон**, а не переписку и стеклянные панели. Источники: `glass.tsx` и [Expo BlurView SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/blur-view/).

Репозиторий [Glass-HQ/liquid-glass](https://github.com/Glass-HQ/liquid-glass) используется как визуальный ориентир. Это библиотека для web/Electron; её WebGPU-рефракция в React Native не портирована. Платформенные материалы, уменьшение прозрачности и переключение темы на физических iOS/Android-устройствах в этой среде не проверялись.

## Проверка зависимостей

`npm audit --json` для сервера сообщил **0** известных уязвимостей. Для дерева мобильного проекта сообщил **3 high**, все по одной цепочке: `expo → @expo/cli → zod@3.25.76`. Это три затронутых записи пакетов, а не три независимые обнаруженные уязвимости.

Источник: [GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5). Advisory описывает чрезмерное потребление памяти Zod при проверке специально подобранных больших коллекций; исправленная версия — 4.6.6. В опубликованной ветке CLI 57 на дату проверки заявлен диапазон `zod ^3.25.76`; совместимого точечного исправления в этой ветке не обнаружено. Принудительная смена major-версии Zod и автоматическое понижение Expo SDK не выполнялись.

В установленном проекте Zod импортируют схемы плагинов/расширений Expo DevTools; исходники клиента и сервера мессенджера его не импортируют. Проверка исходников и web-пакетов указывает на зависимость инструментов разработки. Эксплуатируемость этой уязвимости в данном приложении или процессе сборки **я не могу подтвердить**. Это остающееся предупреждение, а не основание заявлять, что всё дерево зависимостей безопасно.

## Пределы проверки

- Не выполнялись установка и запуск на физических телефонах или мобильных эмуляторах.
- Не проверялись системная клавиатура, разрешения галереи, выбор документов, системное меню «Поделиться» и сохранение токена в Keychain/Keystore на устройствах.

- HTTPS/TLS на публичном домене не проверялся: интеграционные тесты используют локальные HTTP/WS-соединения.
- Сквозное шифрование, группы, каналы, звонки и push-уведомления отсутствуют в объёме этой версии и не заявляются проверенными.
