# INVIZENT (Инвиз): передача проекта в новый чат

Состояние на 2 ноября 2026, версия приложения **0.14.2** (Android/iPhone/Windows).

Чтобы продолжить, вставь этот файл в новый чат и напиши, что делать дальше. Весь код лежит в GitHub, поэтому новый чат начинает с `git clone`.

## 1. Что это

- **INVIZENT** (в приложении «Инвиз») — приватный мессенджер для друзей. Раньше назывался Linea (Линия).
- Клиент: Expo SDK 57 и React Native 0.86. С 0.9.0 анимации и жесты: `react-native-reanimated` 4 + `react-native-worklets`, `react-native-gesture-handler`, клавиатура — `react-native-keyboard-controller`, заряд — `expo-battery`. Собственные нативные модули:
  - LineaSignal — libsignal для E2EE;
  - LineaPhoto и LineaVideo — очистка метаданных фото и видео.
- Хранилище на телефоне: SQLCipher.
- Сервер: Node 24, Fastify и SQLite, запускается через Docker Compose. HTTPS делает Caddy.
- Сквозное шифрование (Signal) соблюдается всегда: ответы, реакции, правки и закрепы передаются внутри шифротекста.
- **Правила проекта, от которых нельзя отступать:**
  - не отключать TLS, аутентификацию и шифрование;
  - не добавлять геолокацию и сканирование установленных приложений;
  - не спрашивать у пользователя пароли и приватные ключи;
  - не делать поддельных IPA;
  - не перекладывать программирование и отладку на пользователя.

## 3. Как собирать

**iPhone.** Сделать push в `main`, дождаться workflow, затем `git clone -b ipa-output https://github.com/stage3hz/linea-build`. В ветке лежит `INVIZENT-iOS-arm64-unsigned.ipa`. Пользователь устанавливает через Appneza; подписка сервиса закончилась, Developer Mode включён. Нужные App Groups для ReplayKit у его профиля не подтверждены. Мака у него нет.

**Android.** Собирается локально в контейнере:
```bash
cd mobile && npm ci
APP_ENV=development npx expo prebuild --platform android --clean --no-install
cd android && ./gradlew assembleRelease
```
- Нужны Android SDK и JDK 21.
- Maven Central отвечает 429, поэтому в `~/.gradle/init.d/` нужен init-скрипт с зеркалом `maven-central.storage-download.googleapis.com`.
- Если после prebuild пропал микрофон или камера, проверь `tools:node="remove"` в AndroidManifest.

**Тесты.**
- Нужен Node 24 (`--test-isolation`). Для e2ee-тестов: `/tmp/linea-signal-tests` с `@signalapp/libsignal-client@0.106.0`; для relay-теста — `npm ci` в `server`.
- Клиент: `node --test --test-isolation=none test/*.test.mjs`. Тест `e2ee-native-interop` пропустить, ему нужен Gradle. Сейчас проходят 328 из 328.
- Сервер: `npm test` в папке `server`, проходят 101 из 101.
- Kotlin-фильтры фото (PhotoPixelsTest) можно прогнать без Android SDK: отдельный gradle-проект с kotlin("jvm"), исходники PhotoPixels.kt + тест (9 из 9).

**Перед каждой сборкой** поднять версию сразу в нескольких местах:
- в `mobile/app.config.js`: поле `version`, строку `appVersion` в комментарии и `versionCode`;
- в `mobile/package.json`;
- в первых двух вхождениях `mobile/package-lock.json`;
- в `android/app/build.gradle`, если не делается prebuild `--clean`.

## 4. Сервер: полезные команды (`/opt/linea`)

- **Обновить файлы из GitHub:**
  `curl -fsSL https://codeload.github.com/stage3hz/linea-build/tar.gz/main | tar -xz --strip-components=1 linea-build-main/<пути>`
- **Применить изменения:** `bash install.sh` (повторный запуск безопасен).
- **AI (FreeLLMAPI):**
  - `bash deploy/ai.sh test` — проверить, что AI отвечает;
  - `bash deploy/ai.sh key <единый ключ>` — подключить единый ключ;
  - `bash deploy/ai.sh setup-code` — получить код первичной настройки.
- **Выход AI через Cloudflare Worker.** Провайдеры блокируют российский IP: Google отвечает «User location is not supported», OpenRouter — 403.
  - `bash deploy/relay.sh setup` — настроить заново;
  - `bash deploy/relay.sh pin` — если AI перестал отвечать: заново найти IP Worker'а через DoH;
  - `bash deploy/relay.sh off` — выключить выход через Worker.
  - Обычный DNS сервера не отдаёт адреса `*.workers.dev`, поэтому IP закрепляется в контейнере через `extra_hosts`.
- **Состояние AI:** работает через ключ Google AI Studio, модель `gemini-3.1-flash-lite`. Ключ OpenRouter отвечал 403, возможно, его нужно перевыпустить.

## 6. Важные исправления (чтобы не наступить снова)

- **«file is not a database».** `withExclusiveTransactionAsync` в expo-sqlite открывает второе соединение без `PRAGMA key`. Запись в хранилище идёт на том же соединении: `BEGIN IMMEDIATE`, затем очередь (`e2ee/vault.native.ts`).
- **«Нет связи с сервером» при любой загрузке.** Глобальный fetch в Expo 57 — это expo/fetch, он не принимает части FormData вида `{uri,name,type}`. Загрузки отправляются собранным вручную multipart-телом: `multipartFile` в `api.ts`.
- **Android, `content://`.** Файлы из галереи сначала копируются в кэш приложения (`media/localCopy.ts`).
- **Android, клавиатура закрывает поле ввода.** При edge-to-edge `adjustResize` не работает, поэтому `KeyboardSafeView` сам добавляет отступ.
- **Тень на Android.** Elevation у полупрозрачного стекла рисовал серый прямоугольник. Elevation отключён.
- **Вылет при «Назад».** Recorder из expo-audio уже освобождён к моменту очистки. Не трогать его в cleanup без try.
- **Видео с фронтальной камеры iPhone.** Зеркальная матрица поворота теперь допустима (`LineaVideo VideoFormat.orientation`). Ошибки видео показывают код причины в квадратных скобках.
- **Микрофон на Android.** `microphonePermission:false` у expo-image-picker блокировал RECORD_AUDIO.
- **Поле ввода не уменьшалось после отправки.** Используется `ComposerInput`: высота берётся по `contentSize`, отступы там уже учтены.

- Android: «Защищённое видео не поддерживается» было ложным: `drmInitData` у обычных записей камеры и `getSampleFlags()==-1` в конце потока (`VideoTracks.kt`, `VideoAudio.kt`).
- Камера кружка: превью 3:4 обрезается кругом (квадратное растягивалось на Android); смена камеры только до записи.

**Файлы до 5 ГБ.**

- Файл больше 20 МБ идёт частями: AES-256-GCM-SIV по 4 МиБ. У каждой части свой nonce (индекс части смешан с последними 4 байтами) и AD `linea-attachment-v2:<fileKeyId>:<index>:<count>`, поэтому части нельзя переставить или отрезать.

- Сервер (`server/src/bigfiles.js`):
  - `GET /e2ee/limits`;
  - `POST /e2ee/uploads {size}` резервирует место;
  - `PUT /e2ee/uploads/:id?offset=N` принимает одну зашифрованную часть, при неверном смещении отвечает 409 с `received`;
  - `POST …/complete`, `DELETE …` для отмены;
  - незавершённые загрузки удаляются через 24 часа;
  - `GET /files/:id` поддерживает `Range`.
- Клиент (`mobile/src/e2ee/attachments.ts`): `encryptAndUploadLarge` читает файл кусками через `File.open()` (новый API expo-file-system: старый `readAsStringAsync` с `position` ограничен 2 ГБ). Скачивание тоже идёт по диапазонам и расшифровывается сразу в файл.
- Большие фото и видео отправляются как файл, без сжатия и без очистки метаданных (как «отправить файлом» в Telegram).
- В чате большой файл сразу появляется пузырём с прогрессом и крестиком (`UploadBubble` в `MessageRow.tsx`). «Повторить» продолжает с того же места.

## Защита от поддельных клиентов (2 ноября 2026)

- **Подписка (Platina) взломом клиента не открывается:** каждая платная функция проверяется сервером по базе (`username.js`, `app.js` оформление/приватность, `bigfiles.js` лимиты, `ai.js`). Выдаёт Platina только `platina-admin.js` на сервере. Локальной лицензии, которую можно «вытащить», нет.
- **Версия клиента:** приложение шлёт `X-Linea-Client: invizent; v=<версия>; p=<платформа>` (`mobile/src/serverConfig.ts` → `APP_VERSION`, **поднимать вместе с версией**). Сервер (`server/src/clientgate.js`) по `MIN_CLIENT_VERSION` отвечает 426 старым сборкам. По умолчанию выключено.
- **Подпись запросов:** изменяющие запросы (POST/PUT/PATCH/DELETE) подписываются `X-Linea-Attest: <ts>.<HMAC-SHA256>` (клиент `mobile/src/attest/`, свой HMAC с проверкой по RFC 4231; сервер `server/src/attest.js`). GET и `/ws` не подписываются: без подписанного входа сессии нет. Режимы `off`/`warn`/`enforce`, окно 10 мин.
  - Ключ в публичном репозитории всегда пустой (`src/attest/key.ts`, тест это проверяет). Сборки получают его из секрета GitHub `ATTEST_KEY` (`scripts/inject-attest-key.mjs`, шаги в iOS и Windows workflow). Для локальной Android-сборки: `ATTEST_KEY=… node scripts/inject-attest-key.mjs` перед сборкой и `git checkout src/attest/key.ts` после.
  - Включение: `bash deploy/attest.sh on` (ключ + warn) → добавить ключ в секреты GitHub → собрать и поставить новые версии → `bash deploy/attest.sh log` пуст → `bash deploy/attest.sh enforce`.
  - Честно: ключ внутри приложения можно извлечь; это планка против простых форков и скриптов и рычаг, который меняется без нового сервера.
- **Исправлено:** `install.sh` при каждом обновлении стирал настройки выхода AI через Worker (`FREELLMAPI_PROXY_*`, `FREELLMAPI_RELAY_*`). Теперь они сохраняются, как и новые `MIN_CLIENT_VERSION`, `REQUIRE_CLIENT_HEADER`, `ATTEST_KEY`, `ATTEST_MODE`.
- `deploy/relay.sh`: запасные способы найти IP Worker'а (AdGuard DoH, обычный DNS по TCP) — в России блокируют DoH Google/Cloudflare.
- Тесты: сервер 135, клиент 343 (8 e2ee/desktop требуют libsignal 0.106.0: `LINEA_SIGNAL_TEST_TOOLS`, `npm ci` в `desktop`).

## Бэкапы (deploy/autobackup.sh)

- Один раз на сервере: `cd /opt/linea && git pull` (или как обычно обновляешь) → `bash deploy/autobackup.sh install`.
  Создаёт ключ `deploy/secrets/backup-age.key`, systemd-таймер (каждую ночь ~04:17 МСК) и сразу делает первый бэкап.
- Архив: снимок базы без остановки сервера (`VACUUM INTO`, `server/src/backup.js`), `uploads/`, `deploy/.env` и `deploy/secrets`.
  Шифрование age. Хранятся 14 последних в `/var/backups/invizent`.
- После каждого архива он расшифровывается во временную папку и проверяется в отдельном контейнере
  (integrity_check, foreign_key_check, совпадение числа строк со снимком). Неудачный архив удаляется, статус в `last-status.json`.
- `bash deploy/autobackup.sh key` — ключ восстановления: хранить ВНЕ сервера. Без него при потере VPS архивы не расшифровать.
- `bash deploy/autobackup.sh remote ИМЯ:путь` — копия в rclone-хранилище (настраивается `rclone config` самим владельцем).
- `bash deploy/autobackup.sh restore ФАЙЛ.age` — проверка архива, подтверждение словом ВОССТАНОВИТЬ, замена данных, запуск api.
- Проверено в Docker с production compose: бэкап → полное стирание `/data` → restore → файлы совпадают побайтно, вход работает,
  аккаунт, созданный после снимка, отсутствует (точка во времени). systemd-установка на самом VPS ещё не проверялась.

## Несколько серверов: выбор по скорости и автопереключение (клиент)

- Аккаунт привязан к постоянному «realm» `SERVER_URL` — ключи шифрования и история на устройстве не зависят от того,
  через какой сервер идёт связь. Адрес подключения выбирает `mobile/src/servers/pool.ts`.
- Кандидаты: встроенные (`SERVER_URL`, `LEGACY_SERVER_URLS`) + список, подписанный владельцем (Ed25519, `@noble/curves`).
  Ключи проверки — `mobile/src/servers/key.ts` (публичные, не секрет; пусто = только встроенные серверы).
- Разрешены только `https://*.invizent.com` / `*.invizent.ru` (то же правило в `desktop/main.cjs` и `installDesktopFetch.ts`).
- Замер `/health` при старте, после нового списка и каждые 5 минут; переключение, только если другой сервер быстрее на ≥40 мс и ≥30 %.
  Ошибка сети или 502/503/504 → сервер пропускается сразу, чтения и недоставленные запросы повторяются на следующем.
- Сервер отдаёт список как есть: `GET /servers` из `deploy/secrets/servers.json` (`SERVER_LIST`).
- Владелец: `node deploy/servers.mjs keygen ключ.pem` (на своём компьютере; ключ держать в секрете) → публичный ключ в `key.ts`;
  `node deploy/servers.mjs sign ключ.pem list.json servers.json` → копия на каждый сервер. Каждый новый список — с бо́льшей `version`.
- Проверено на стенде (3 сервера, задержки 150/20/80 мс, ПК-версия): выбран самый быстрый; при остановке быстрого
  и затем второго сообщения уходили без ошибок через оставшийся. Репликация базы между серверами — ещё не сделана.
