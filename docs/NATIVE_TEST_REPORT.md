# Проверка нативного Signal-модуля и APK 0.3.0

Дата проверки: 28 октября 2026 года.

## Основа реализации

Использована официальная **libsignal 0.106.0**. Проверены тег `v0.106.0`, Java/Kotlin API, Swift API и наличие CocoaPods-спецификации именно этой версии. Android подключает `org.signal:libsignal-client:0.106.0` и `org.signal:libsignal-android:0.106.0` из официального Maven-репозитория Signal. Swift подключает `LibSignalClient` из того же тега.

Исходники: [официальный тег](https://github.com/signalapp/libsignal/tree/v0.106.0), [CocoaPods specification](https://github.com/signalapp/libsignal/blob/v0.106.0/LibSignalClient.podspec), [релиз](https://github.com/signalapp/libsignal/releases/tag/v0.106.0).

Нативный модуль `LineaSignal` генерирует ключи и выполняет Signal/AES-GCM-SIV через SDK. Собственной реализации криптографических примитивов нет. Для каждого вызова создаётся отдельное хранилище в памяти. Нативный код не сохраняет состояние или открытые файлы на диск и не пишет их в журналы.

До отправки и расшифровки обязательно явное закрепление подтверждённого ключа через `trustIdentity`. Отсутствующий или изменившийся ключ не принимается. Локальный адрес задаётся при создании состояния; числовой deviceId равен 1, UUID аккаунта и устройства входят в имя адреса. Привязку полезной нагрузки к чату, отправителю, получателю и устройствам дополнительно проверяет JS-слой.

## JVM: тот же Kotlin-код, что входит в Android-модуль

Скомпилирован и выполнен `SignalCore.kt`, подключённый из `android/src/main/java`. Тесты не заменяют криптографию заглушками. Результат: **7 тестов пройдены, 0 ошибок**.

| Проверка | Что подтверждено |
| --- | --- |
| Двусторонний обмен и ratchet | Первое prekey-сообщение, ответ, следующий шаг; состояние сериализуется между вызовами |
| Повторная доставка | Уже обработанный шифротекст отклоняется после восстановления сохранённого состояния |
| Повреждение шифротекста | Сообщение отклоняется; исходное состояние остаётся пригодным для правильного сообщения |
| Доверие и смена ключа | Отправка/приём без закреплённого ключа запрещены; заменить существующий ключ нельзя |
| Подпись prekey и Kyber replay | Повреждённая подпись отклоняется; перенос повторного initial-сообщения на другой явно доверенный адрес блокируется сохранённым Kyber tuple |
| Пополнение ключей | Публикуются только новые публичные prekeys; старые приватные ключи сохраняются для задержанных сообщений; предел 1000 отклоняет дальнейшее пополнение без удаления ключей |
| AES-256-GCM-SIV | Совпадение открытых данных после расшифровки; повреждённые данные, другой AAD и неверная длина nonce отклоняются |

Ключ Kyber используется как last-resort и сохраняется после первого применения; набор уже использованных `(kyberId, signedPreKeyId, baseKey)` также сохраняется. Проверяется именно поведение официального протокола: имя адреса само по себе не заменяет проверку контекста сообщения приложением.

Тесты находятся в `mobile/modules/linea-signal/android/src/test/java/expo/modules/lineasignal/SignalCoreTest.kt`. JVM-проект — `mobile/modules/linea-signal/jvm-tests`.

## Совместимость Node ↔ Kotlin

`mobile/test/e2ee-native-interop.test.mjs` выполняет живой обмен между официальным Node SDK 0.106.0 и тестовым процессом, использующим Kotlin `SignalCore`.

Подтверждены Node prekey → Kotlin, Kotlin reply → Node, обработка сообщений не по порядку, отклонение повтора и повреждения, сохранность правильного состояния после ошибки, невозможность прочитать старый архив новым приватным ключом. AES-GCM-SIV даёт одинаковый шифротекст на одинаковых ключе/nonce/AAD и отклоняет изменённый AAD. Тестовый JSON-lines процесс не включается в APK.

## iOS и границы проверки

Swift-модуль содержит действительные вызовы соответствующих API официальной версии 0.106.0. Подключение CocoaPods фиксирует SHA-256 опубликованного FFI-архива: `ddfa5ac6fd6e0da9ebe4eb23890af048140aec1a3e916d3eccadc1036627152f`.

**На Linux не выполнялись Xcode/iOS-сборка и проверки на физических Android/iPhone.** Обзор Swift-исходников не является проверенной iOS-сборкой. Native module отсутствует в Expo Go; веб-версия должна отказывать в операциях E2EE, если нативный модуль недоступен. Эти результаты также не являются независимым аудитом всего приложения.

## Журнал решений и проверок

1. Зафиксирована 0.106.0: эта версия одновременно предоставляет необходимые PQ API и CocoaPods-интеграцию. Подтверждено официальными исходниками/релизом.
2. В контракт добавлены локальный адрес и `trustIdentity`: SDK требует localAddress, а первый входящий ключ должен совпасть с подтверждённым пользователем ключом. Missing trust запрещён в обоих направлениях.
3. Хранилище сделано отдельным на каждый вызов: неудачная операция не возвращает частично изменённое состояние. Обмен, ошибки и повторная загрузка проверены JVM-тестами.
4. Сохраняются старые prekeys и Kyber replay tuples: это необходимо для задержанной доставки и защиты last-resort ключа от повторов. Граница ключевого пула проверена тестом.
5. Исправлена неверная предпосылка одного теста о первой доставке под другим явно закреплённым адресом: проверка приведена к фактической гарантии SDK, а контекст приложения проверяется внутри зашифрованной полезной нагрузки. Криптография для обхода результата теста не менялась.
6. Новый JDK использует системное доверенное хранилище CA для окружения сборки после воспроизведённой ошибки PKIX. Проверка сертификатов TLS не отключалась.
7. Сборочный plugin проверен повторным prebuild; существующие SQLCipher-настройки и manifest-настройки не заменялись.

8. Реальная Android-компиляция выявила конфликт: React Native принудительно выставляет Java target 17 в finalizeDsl. Удалено избыточное требование target 21 у моста/приложения; JDK 21 сохранён. Повторная компиляция Kotlin и Java Android-модуля прошла. Проверка совместимости JVM targets не отключалась.

9. После согласованного JS freeze зафиксированы 52 входных файла. Финальный APK собран, все исходные хеши совпали; проверены подпись, manifest, DEX, native libraries, SQLCipher, ABI и выравнивание 16 KiB. Логи и метаданные сохранены рядом с отчётом.

10. После успешной сборки удалены только уже распакованные и проверенные установочные архивы SDK/JDK (389,691,980 байт). Установленные инструменты, исходники и результаты проверок сохранены для повторной сборки.
