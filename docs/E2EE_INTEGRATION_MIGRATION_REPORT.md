# Исторические интеграционные проверки: переход на E2EE-only

Изменены только [`server/test/integration.test.js`](../server/test/integration.test.js) и новый [`test/support/relay-fixtures.js`](../server/test/support/relay-fixtures.js). Производственный сервер и отдельный `e2ee-relay.test.js` этим изменением не затронуты.

Сохранены все **16** прежних интеграционных сценариев. Fixture больше не включает `allowLegacyPlaintext`: используется обычная конфигурация production server. Для тестовых аккаунтов регистрируются устройства с синтетическими публичными ключами, а положительные отправки содержат только `clientId` и `encrypted`. Байты конвертов случайные, структурно допустимые для relay-контракта; они не являются реально сформированными сообщениями Signal. Подписи и ключи также синтетические. Набор проверяет API, доступ и хранение, а не шифрование или расшифрование.

## Сохранённые проверки

- Регистрация, приватные сеансы, вход, поиск и валидация данных.
- Один диалог на пару, непрочитанные сообщения, история и пагинация.
- Запрет третьему пользователю читать, отправлять или отмечать сообщения чужого диалога.
- Повтор с тем же `clientId` и тем же ciphertext возвращает **200** и прежний ID. Изменение одного байта под тем же ключом даёт **409**; пагинация подтверждает, что сохранённое содержимое осталось прежним.
- Монотонные отметки прочтения и отказ принимать ID сообщения другого диалога.
- Вложения отправляются через `/e2ee/files` и доступны другому участнику только после привязки. Сохраняются проверки владельца, запрета чужой привязки, повторной привязки, доступа без авторизации и токена в URL.
- `/uploads` проверяется как путь аватара: действительный PNG распознаётся при неверном MIME, HTML под видом PNG отклоняется, предел размера сохраняется. Владелец может читать ещё не выбранный PNG; другим пользователям доступ появляется только при назначении аватара.
- Чужой аватар и opaque-вложение нельзя назначить себе как аватар; очистка аватара снова закрывает доступ постороннему аккаунту.
- После перезапуска сохраняются аккаунты, сеансы, зашифрованные конверты, файлы и публичная идентичность устройства.
- WebSocket передаёт тот же opaque-конверт участникам, сохраняет приватность событий прочтения/набора текста, закрывается после отзыва сеанса и не допускает неавторизованного наблюдателя.
- Пустые/слишком большие конверты, недопустимый `clientId` и plaintext отклоняются без сохранения сообщений. Проверка большого конверта использует 65537 байт при пределе 64 КиБ.
- Ограничения попыток входа, срок сеанса, HTTP Origin и исключение Origin для нативного WebSocket сохранены.

Отдельное правило запрета скачивания старых plaintext-вложений чата находится в тестах владельца `e2ee-relay.test.js`; здесь не создан повтор этого сценария и не возвращён устаревший plaintext fixture.

## Фактический запуск

После сигнала готовности production-изменений выполнено из `server`:

```sh
node --test --test-isolation=none test/integration.test.js
```

Полный вывод одного запуска сохранён в [server-integration-e2ee.txt](evidence-v05-build/server-integration-e2ee.txt). Это отдельный выделенный набор, а не результат всего server suite. Проверки клиентов на настоящем libsignal и аудит криптографии этим запуском не заменяются. Тестовые исходники после успешного запуска заморожены.
