# Геолокация и изоляция приложений: версия 0.5.1

Требования пользователя: приложение не определяет местоположение и изолирует свои данные от других приложений. Это дополнение к обязательному E2EE личных сообщений. Ни подпись IPA, ни запуск новой версии на физическом iPhone этим отчётом не подтверждаются.

## Реализуемая граница

Приложение хранит свои данные в собственном контейнере. Фото и файлы импортируются по выбору пользователя через системные механизмы. Копирование, меню «Поделиться», открытие страницы музыкального сервиса или настроек ОС выполняются по явному нажатию. Эти разрешённые пользователем передачи не объявляются полностью запрещённым обменом с внешним миром.

Apple описывает песочницу как изоляцию данных сторонних приложений с доступом к внешним ресурсам через предоставленные системой сервисы. Она опирается на ОС и подписанные entitlements. [Security of runtime process](https://support.apple.com/guide/security/security-of-runtime-process-sec15bfe098e/web). Для Android приватные внутренние файлы и внутренний cache также отделены от других приложений. [App-specific storage](https://developer.android.com/training/data-storage/app-specific).

Эта модель не даёт доказательства защиты от скомпрометированной ОС, действий самого владельца устройства или всех возможных сторонних SDK. Я не могу подтвердить абсолютную изоляцию на физическом телефоне без проверки установленной подписанной сборки.

## Что проверено в коде

| Область | Факт и источник в проекте |
| --- | --- |
| GPS и геокодирование | В `mobile/src`, собственных Kotlin/Swift-модулях и `server/src` не обнаружены вызовы определения координат, `CLLocationManager`/`CLGeocoder`, GPS watchers или GeoIP-запросов. |
| Галерея | `attachments/gallery.ts` получает метаданные ассетов используемым SDK методом `Query.exeForMetadata`; проверенная реализация `AssetMapper.toMetadata` не возвращает координаты. Неиспользуемые методы геолокации внутри зависимостей не выдаются за фактический сбор данных приложением. |
| Разрешение медиагеолокации | В `app.config.js` выключено `isAccessMediaLocationEnabled`; новая конфигурация дополнительно запрещает coarse/fine/background/media location permissions Android. |
| Буфер обмена | Найдены записи через `Clipboard.setStringAsync` в обработчиках кнопок чата, профиля и AI. Автоматические чтения clipboard в проверенном прикладном коде не обнаружены. |
| Приложения и управление устройством | В проверенном прикладном коде нет запросов списка установленных приложений, accessibility-сервиса, перехвата экрана или интерфейса управления другим приложением. Элементы доступности UI для VoiceOver/TalkBack не являются accessibility-сервисом управления телефоном. |
| Секреты | `storage.ts`, `auth/recoveryStorage.ts`, `e2ee/vault.native.ts` используют SecureStore с `WHEN_UNLOCKED_THIS_DEVICE_ONLY`. Ключи Signal находятся в SQLCipher vault; его ключ не равен паролю аккаунта. |
| Файлы | Подготовка и расшифровка медиа используют cache приложения; музыка сохраняется в его `Paths.document`. Временные расшифрованные вложения удаляются при завершении просмотра и очищаются при старте по соответствующим префиксам. Это проверка кода жизненного цикла, а не доказательство отсутствия остаточных данных после любого сбоя ОС. |
| Выход наружу | `shareAsync`, системный picker и `Linking.openURL/openSettings` вызываются из действий пользователя. AI — отдельный согласованный внешний запрос; личные переписки не добавляются автоматически. |

## Защита сборочной конфигурации

Подготовщик в `tools/ios-cloud-setup` добавляет завершающую проверку iOS-проекта. Она отклоняет `NSLocation*`, location background mode, `LSApplicationQueriesSchemes`, App Groups и явно заданные keychain access groups. Для `UIFileSharingEnabled` и `LSSupportsOpeningDocumentsInPlace` допускаются только отсутствие или строгое `false`. Общие каталоги Documents и редактирование чужого документа на месте не включаются; системный импорт выбранного файла копирует его в контейнер приложения.

Для будущих Android-сборок явно заблокированы location permissions, overlay, массовый просмотр пакетов, статистика использования приложений, управление общим внешним хранилищем и доступ к контактам/календарям. Точный список находится в подготовщике и его отчёте.

**Ранее переданный APK 0.5.0 не изменился.** В его manifest было разрешение `SYSTEM_ALERT_WINDOW` от сборочного стека Expo. Использование overlay прикладным кодом не обнаружено, но старому бинарному файлу нельзя приписывать новые запреты версии 0.5.1. Для проверки Android 0.5.1 нужен новый APK и его manifest.

Генерация проекта с `--no-install` проверяет конфигурацию и файлы до CocoaPods/Xcode. Подписанный IPA нужно отдельно проверить на фактические Info.plist, entitlements, permissions и поведение. Подробности локальных проверок — отчёт iOS-комплекта.

## Фото, видео и данные внутри файлов

Штатный путь фото/видео выполняет очистку до E2EE. Аватар также проходит `ProfileScreen → Api.upload → prepareMediaForUpload`. `exif: false` у picker не считается единственной защитой: после него выполняется обработка байтов. В поддерживаемых PNG/JPEG/MP4 удаляются приватные метаданные; необходимые сведения декодирования и допустимые HDR-поля рассматриваются отдельно.

Границы, которые нельзя скрывать:

- Произвольные PDF, ZIP, аудиофайлы и другие generic-вложения сохраняют выбранное пользователем содержимое. Внутри него могут уже находиться адреса или координаты. Это не определение геолокации приложением и не универсальная очистка любых документов.
- Backend `/uploads` сам не очищает изображение: старый или сторонний клиент может загрузить аватар с метаданными. Штатный текущий клиент перед отправкой очищает его; серверная защита от обхода другим клиентом остаётся отдельным незакрытым вопросом.
- Byte-sniff ISO-BMFF в текущем медиакоде ожидает `ftyp` первым. Переименованный MP4 с ведущим `free/wide` и generic MIME может остаться обычным файлом. При корректном имени или MIME видео используется видеопуть. Это статически обнаруженная граница, а не проверенная здесь воспроизводимая утечка.

Поэтому корректное обещание этой версии: **приложение не определяет и не отслеживает местоположение; поддерживаемые фото и видео обрабатываются штатным клиентом перед отправкой**. Обещание отсутствия координат в любом пользовательском файле этим кодом не обеспечивается.

## Сетевой IP

Сервер использует `request.ip` для ограничения попыток входа, восстановления и WebSocket-подключений. В проверенном коде лимитеры и активные соединения держат IP в памяти; постоянной записи IP или координат в прикладную БД не обнаружено. Обычное request-логирование Fastify отключено, в Caddyfile нет access-log директивы. Служебные Docker stdout/stderr остаются.

Поведение инфраструктуры хостинга и внешних музыкальных/AI-провайдеров этим исходным кодом не контролируется. Отсутствие их собственного определения региона по IP я не могу подтвердить.

## Бессрочная Platina

Подписка закрепляется за UUID аккаунта и выдаётся доверенной серверной командой. Она не добавляет мобильному приложению App Groups, доступ к другим приложениям, ключи чужих переписок или системные привилегии. Это отдельное прикладное право, описанное в [PLATINA_OWNER_0.5.1.md](PLATINA_OWNER_0.5.1.md).
