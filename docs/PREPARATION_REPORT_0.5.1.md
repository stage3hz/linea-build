# Линия 0.5.1: фактическая подготовка и проверка

Дата: 28 октября 2026 года. Обновление подготовлено отдельной копией проверенного исходного архива 0.5.0. Опубликованный Android APK 0.5.0 и исходники, с которыми он был собран, не изменялись.

**Результат этой передачи — исходники 0.5.1, серверный комплект и инструменты облачной сборки iOS. Нового APK, подписанного IPA, работающего VPS или снимка экрана физического iPhone нет.** Expo-экспорт и prebuild не выдаются за компиляцию и запуск нативного приложения.

## Что изменено

### Бессрочная Platina

Сервер хранит административную выдачу без даты окончания и привязывает её к постоянному UUID. Команда `lookup` разрешает текущее публичное имя в UUID; изменяющая команда `grant-permanent` принимает UUID, а не имя. Смена ника, перезапуск и штатное восстановление пароля не снимают право. Другой аккаунт, занявший освобождённое имя, его не получает.

Миграция SQLite 4 → 5 снимает NOT NULL только с поля окончания выдачи, сохраняя конечные сроки, отзывы и audit. Она выполняется транзакционно. До обновления существующей базы нужна согласованная резервная копия: сервер 0.5.0 не открывает схему 5.

В мобильном исходном коде добавлена надпись **«Бессрочно»** и поддержка постоянного статусного эмодзи без таймера окончания. Одного отсутствующего срока недостаточно: клиент требует явный серверный признак. Публичной кнопки/HTTP-маршрута для выдачи нет; новая роль администратора или доступ к чужой переписке не создаются. Реальные аккаунты при подготовке не использовались и никому право не выдавалось.

Порядок выдачи, отзыва и точный API: [PLATINA_OWNER_0.5.1.md](PLATINA_OWNER_0.5.1.md).

### Подготовка iOS с одного iPhone

В полный исходный комплект включён [tools/ios-cloud-setup](../tools/ios-cloud-setup/README.md). Его инструкция использует iPhone для управления удалённым VPS; EAS выполняет iOS-сборку на своей macOS-машине. Собственный Mac не обязателен для этого маршрута. Нужны реальные Expo-проект и Apple signing credentials, подходящие для устройства и bundle identifier.

Подготовщик сохраняет исходную конфигурацию, проверяет её контрольные суммы, не перезаписывает посторонние изменения и принимает только публичные идентификаторы проекта. В переданном исходном комплекте `owner` и `projectId` не подставлены вымышленными значениями.

Включено `ios.useFrameworks: static` для выбранной интеграции libsignal. Требование `use_frameworks!` подтверждено локальными байтами официального README libsignal v0.106.0; URL, SHA-256 и способ получения записаны в [VERIFICATION.json](../tools/ios-cloud-setup/VERIFICATION.json). Это устранение документированного пробела конфигурации, а не исправление воспроизведённой ошибки Swift-компилятора.

### Геолокация и изоляция

Добавлена завершающая проверка generated iOS Info.plist/entitlements. Она запрещает location keys/background mode, явные App Groups и общие keychain groups, app query schemes и включение общего доступа к Documents. В Android-конфигурации добавлены запреты геолокации, overlay, широкого доступа к хранилищу, списку/использованию приложений, контактам и календарям. Полный список и отрицательные проверки записаны в отчёте комплекта.

Прикладной код не определяет координаты и не читает clipboard автоматически в проверенных путях; импорт, копирование и экспорт привязаны к действиям пользователя. Это анализ исходников и конфигурации, а не полный аудит всех SDK или установленного приложения. Подробные факты и границы — [PRIVACY_0.5.1.md](PRIVACY_0.5.1.md).

В серверном прогоне использовались настоящие SQLite и отдельные процессы CLI, синтетические аккаунты и временные базы. Проверены сохранение старых данных, отказ по неверным параметрам, отзыв, постоянство UUID, восстановление и повторное занятие старого имени. Первоначальная блокировка subprocess песочницей сохранена как отдельная диагностика, а не выдана за успешную проверку CLI.

Мобильный прогон в этой итерации ограничен изменённой моделью статуса, TypeScript и iOS-экспортом. Полный набор 303 мобильных тестов и нативные тесты предыдущего выпуска не повторялись: они остаются историческим свидетельством 0.5.0 в [TEST_REPORT.md](TEST_REPORT.md). Код криптографии и медиамодулей в 0.5.1 не менялся. Предыдущие результаты не объявляются испытаниями нового бинарного файла.

Контрольные суммы текущего исходного снимка находятся в [SOURCE_MANIFEST_0.5.1.json](SOURCE_MANIFEST_0.5.1.json). Это фиксация исходников, а не manifest успешно скомпилированного APK/IPA. В комплекте сохранён прежний BUILD_SOURCE_MANIFEST_0.5.json как исторический документ. Архиватор проверяет соответствие текущих байтов новому снимку и неизменённым manifest медиамодулей.

## Что ещё не подтверждено

- CocoaPods resolution/install, компиляция Swift/Xcode, EAS cloud build, подпись и создание IPA. Наличие исходников iOS не доказывает успешную нативную сборку.
- Запуск и визуальное отображение 0.5.1 на физическом iPhone/Android. Скриншот из настоящего приложения не получен.
- Новый Android APK и итоговый Android manifest. Прежний APK 0.5.0 содержит `SYSTEM_ALERT_WINDOW`; новые запреты относятся к будущим сборкам.
- Реальные VPS, DNS для .ru/.com, TLS на пользовательском сервере и подключение Expo/Apple account. Подготовленные команды не выполнялись на чужой инфраструктуре.
- Пригодность ранее упомянутого архива Premium для подписи. В доступных файлах он не найден; для проверки нужен сам архив. Публичные project ID/owner/bundle ID не заменяют signing credentials.

По-прежнему отсутствуют группы, каналы, звонки, фоновые APNS/FCM, полноценные платежи Platina и полный функциональный паритет Telegram. Бессрочное право включает только уже реализованные возможности Platina. Неизменённые ограничения фото/видео, сторонних музыкальных каталогов и AI описаны в README и базовых отчётах.

Для установки с iPhone начните с [инструкции облачной сборки](../tools/ios-cloud-setup/README.md), для сервера — с [DEPLOY_FROM_IPHONE.md](DEPLOY_FROM_IPHONE.md). Для реальной выдачи Platina после регистрации используйте найденный UUID и административные команды из отдельного отчёта.
