## Что проверено

| Область | Проверяемое поведение |
| --- | --- |
| Регистрация без контактов | Для нового аккаунта требуются логин, пароль, отдельное слово входа и отдельное слово восстановления. Поля почты и телефона не принимаются. Пароли короче 15 или длиннее 128 кодовых точек и пароли только из пробелов отклоняются; намеренные пробелы в содержательном пароле сохраняются. |
| Хранение секретов | У синтетических аккаунтов пароль и оба слова хранятся как солёные хеши `scrypt-v2`; одинаковые секреты получают разные хеши. Ответы регистрации и профиля не содержат этих хешей. Сессионные и восстановительные токены в проверяемых таблицах представлены SHA-256-хешами. |
| Слово входа | Новый аккаунт не входит с правильным паролем и отсутствующим, неверным или восстановительным словом. Ошибка не показывает, какой из введённых секретов не подошёл. Поддерживаются короткие русские и английские слова разрешённой длины. |
| Нормализация слов | Проверены NFC, регистр и внешние пробелы для русских и английских слов. Нормализация слова не меняет чувствительность основного пароля к намеренным пробелам. |
| Три попытки | Первые две ошибки оставляют 2 и 1 попытку; третья блокирует восстановление на 24 часа. Правильная третья попытка работает. Изменение IP и перезапуск сервера не сбрасывают бюджет. Обычный вход остаётся доступным и не снимает блокировку восстановления. |
| Конкурентная проверка | Четыре одновременно отправленных неверных слова не резервируют больше трёх попыток. Проверяется состояние реальной SQLite после запросов. |
| Существующий и отсутствующий логин | Последовательные ошибки имеют одинаковые публичные ответы и бюджет. Проверены перезапуск, окончание блокировки и одинаковое истечение частичного бюджета после суток неактивности. |
| Ожидание восстановления | Сервер запрещает изменение пароля до `readyAt`, включая момент за 1 мс до окончания десяти минут. Статус и время готовности сохраняются после перезапуска. Через 20 минут после готовности запрос истекает. Опрос статуса использует отдельный лимит. |
| Запросы и отмена | Запрос виден только владельцу аккаунта. Собственные WebSocket-сессии получают уведомление без секретов; чужой аккаунт не получает его и не может отменить запрос. Отмена окончательно делает токен недействительным. |
| Гонки восстановления | При параллельных reset/reset один запрос может примениться только один раз. При cancel/reset отмена и изменение пароля не могут оба успешно зафиксироваться. Используются настоящие конкурентные запросы, KDF и база данных. |
| Ограниченный токен | Токен восстановления не даёт доступа к `/me` и списку устройств. Новый запрос отменяет прежний токен. Неизвестные поля и неверный новый пароль не поглощают действующий запрос. Повтор уже использованного токена отклоняется. |
| Завершение восстановления | Меняется только пароль; оба запомненных слова сохраняются. Автоматическая новая сессия не создаётся. Все прежние HTTP-сессии и реальные WebSocket-соединения аккаунта отзываются; чужой аккаунт сохраняет доступ. |
| Настройки безопасности | Изменение пароля или слова требует текущего пароля и текущего слова входа, кроме старого аккаунта без настроенного слова. Изменения отзывают предыдущие сессии и запросы восстановления. Слова должны отличаться друг от друга и от основного пароля. |
| Список устройств | Публичные идентификаторы сессий не являются bearer-токенами или их хешами. Проверены текущая сессия, отзыв одной сессии, всех остальных, самой текущей и запрет отзыва чужой сессии. |
| Миграция v1 | База со старой схемой, независимым настоящим хешем `scrypt-v1`, коротким паролем и существующей сессией открывается и сохраняет аккаунт. Проверены стабильный публичный ID сессии, перезапуск, постепенная настройка обоих слов и `securitySetupRequired`. Разложенный Unicode и перевод строки продолжают проверяться по прежним правилам v1. |
| Устаревший асинхронный вход | Старый login задерживается после настоящей проверки обоих секретов через внутренний тестовый барьер. За это время выполняется настоящий reset. После продолжения login получает отказ и не создаёт новую сессию. |

Существующие 16 сценариев дополнительно проверяют приватность чатов и файлов, доставку сообщений и уведомлений WebSocket, идемпотентность отправки, пагинацию, отметки прочтения, профили, перезапуск, выход, срок сессий, ограничения запросов и правила Origin. Для нового контракта в их фикстуры добавлены обязательные слова; прежние предметные проверки сохранены. Эти исторические проверки явно включают `allowLegacyPlaintext` при создании тестового сервера; обычный сервер такой режим не использует. Новый зашифрованный транспорт проверяется отдельными сценариями, а клиентская криптография описана в [E2EE_TEST_REPORT.md](E2EE_TEST_REPORT.md).

## Метод и пределы результата

Каждый сценарий создаёт собственную временную SQLite и использует вымышленные учётные данные. Проверки HTTP выполняются через Fastify injection; проверки WebSocket используют реальные соединения с локальным сервером. Scrypt, токены и транзакции не подменены моками. Для границ десяти минут, двадцати минут и суток применяется управляемое серверное время: тест не ждёт эти интервалы в реальном времени. Единственный внутренний барьер управляет порядком выполнения проверки гонки login/reset; он не подменяет проверку пароля и недоступен через HTTP или переменные окружения.

После первого фактического результата выполнен ограниченный просмотр кода: резервирование попыток происходит до асинхронной проверки, изменения проверяют актуальную версию и хеши непосредственно перед синхронной транзакцией, а reset повторно проверяет запрос после KDF. Обнаруженных блокирующих дефектов в просмотренных путях нет. Это не независимый аудит безопасности, проверка реального Android/iPhone или доказательство отсутствия всех уязвимостей.

Пароль и два запомненных слова относятся к одному типу фактора — знанию. Они не образуют MFA. Ограничение в три попытки уменьшает онлайн-перебор, но короткое распространённое слово остаётся угадываемым. Десятиминутное ожидание предоставляет активной сессии время для отмены и само по себе не доказывает личность. После восстановления слова сохраняются по выбранному пользовательскому сценарию.

Тесты не проверяют распределённое развёртывание, TLS на внешнем домене, push на выключенном устройстве, ручной ввод/запрет вставки в мобильной форме или сквозное шифрование переписки. Бюджет восстановления хранится в SQLite; остальные лимиты процесса требуют отдельного решения при запуске нескольких серверов.

## Первичные рекомендации, использованные при оценке

- [NIST SP 800-63B-4: authenticators](https://pages.nist.gov/800-63-4/sp800-63b/authenticators/) — длина пароля, Unicode, нормализация и типы факторов.
- [OWASP Forgot Password Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Forgot_Password_Cheat_Sheet.html) — ограниченные запросы восстановления, общие ошибки и отзыв сессий.
- [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html) — параметры scrypt; выбранная сервером конфигурация `N=32768, r=8, p=3` входит в приведённые варианты.
- [OWASP Session Management Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html) — повторное подтверждение важных изменений и управление сессиями.

Секретные слова пользователя не описываются как случайные одноразовые коды восстановления и не дают оснований заявлять соответствие всей системы NIST.
