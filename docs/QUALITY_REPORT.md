# Проверка качества Linea 0.3

Дата: 28 октября 2026 года. Проверена серверная часть авторизации и зашифрованной доставки; инструменты `ub-mode` запущены на отдельной копии исходников. Это отчёт о конкретных проверках, а не сертификат готовности к промышленной эксплуатации.

## Результат

- **Финальный серверный набор: 45 из 45 тестов прошли**, без пропущенных тестов, за **168,506 с**. Проверка синтаксиса `npm run check` также прошла; в неё включены новые `auth.js` и `e2ee.js`.
- **Crapper: критерий CRAP < 10 выполнен для 49 из 70 функций.** Для 21 функции критерий не выполнен; максимальный CRAP — **95,9039**. Команда завершилась кодом 2, обозначающим превышение порога.
- **Dryer: в поддержанном мобильном TypeScript/TSX осталась одна пара с оценкой 0,84**, превышающей установленный порог 0,8. Подробности ниже.
- **Mutator: в выбранной группе валидаторов реально проверены 39 мутаций: 37 обнаружены тестами, 2 остались**, результат **94,9%**, код завершения 3. Это выборочная проверка; остальные 99 найденных позиций мутации в модуле доставки не исполнялись.

Полный критерий `ub-mode` по сложности, дублированию и отсутствию выживших мутаций **не достигнут**. Большой рефакторинг работающего приложения ради изменения чисел в этом проходе не проводился.

## Серверные тесты и покрытие

Финальный запуск включал 19 тестов авторизации, 16 прежних интеграционных тестов и 10 новых проверок транспорта шифрованных сообщений. Прежние тесты открытого текста явно включают внутренний режим `allowLegacyPlaintext: true`; в обычном запуске сервера этот режим выключен, и переменной окружения для его включения нет.

Новые проверки охватывают отказ от незашифрованных сообщений по умолчанию, скрытие прежней истории без удаления данных, границы формата публичных ключей, доступ к устройствам только для владельца и собеседника, атомарное расходование одноразовых ключей и защиту от их повторной публикации. Проверены точный набор устройств получателей, безопасный повтор отправки после изменения списка устройств, непрозрачные WebSocket-события, приватность файлов до прикрепления к сообщению, отзыв устройств вместе с их сессиями и последовательное чтение входящих сообщений с пагинацией по чату.

Серверные криптографические фикстуры содержат **синтетические байты**: они проверяют поведение ретранслятора и права доступа, а не корректность Signal Protocol. Проверки реальной клиентской библиотеки описываются отдельно в отчётах интеграции мобильной части.

Файл запуска `index.js` не загружался этими интеграционными тестами. В общей таблице Node он отсутствует; Crapper корректно считает покрытие его `integerEnv` равным 0%. Синтаксис `index.js` проверен отдельно.

В этой среде тестам необходим флаг `--test-isolation=none`. Запуски без него, которые показали только имя файла вместо отдельных тестов, не засчитывались. Две попытки WebSocket-проверок в ограниченной песочнице получили `listen EPERM` на `127.0.0.1`; финальный набор запускался с разрешёнными временными локальными сокетами, без публичного развёртывания.

## Dryer: найденное повторение

Первый проход обнаружил сходство **0,88** между `formatListTime` и `formatDay` в `mobile/src/theme.tsx`: обе функции самостоятельно определяли сегодня/вчера и выбирали формат даты. После выделения общей классификации дня повторный запуск дал **0,84** для оставшихся оболочек форматирования. Порог 0,8 пока превышен.

Это структурная оценка кандидатов инструмента, а не процент дублированных строк приложения. Для JavaScript сервера, Kotlin и Swift данный запуск Dryer результата не даёт. Исходный отчёт: [mobile-dry.edn](quality/mobile-dry.edn).

## Mutator: выполненная выборка и оставшиеся результаты

Первый проход по выбранным 41 позициям дал 32 обнаруженные тестами мутации и 9 выживших. Он выявил отсутствие явных положительных проверок допустимых крайних значений идентификаторов ключей и регистрации, а также точного порядка нормализованных получателей.

Добавлены проверки `0` и `2³¹−1` для идентификаторов ключей, `1` и `16383` для регистрации, сортировки по пользователю и устройству, пустого и максимального по размеру конверта, максимального числа конвертов и вложений. Убрана только дублирующая проверка пустой Base64-строки: минимальный размер декодированных данных проверяется в одном месте. Эти изменения проверены отдельным положительным запуском, затем настоящим повторным запуском Mutator.

| Функция | Обнаружены тестами | Остались |
|---|---:|---:|
| `uuid` | 3 | 0 |
| `integer` | 6 | 0 |
| `base64` | 10 | 2 |
| `curvePublicKey` | 2 | 0 |
| `signedPreKey` | 1 | 0 |
| `parseEncryptedMessage` | 15 | 0 |
| **Выборка** | **37** | **2** |

Два оставшихся изменения в `base64` ослабляют раннее ограничение длины закодированной строки либо раннюю проверку её алфавита. Последующие проверки фактического размера и канонического Base64 по-прежнему отвергают некорректный JSON-ввод, поэтому функциональные тесты сохраняют результат 400. Расход памяти и время до отказа могут измениться: такой ресурсный эффект данным набором тестов не доказан. Выжившие изменения не скрывались и не объявлялись обнаруженными.

Выбраны 39 из 138 найденных позиций; **99 остальных позиций не исполнялись**. Использовался `--no-coverage` для принудительного запуска выбранных позиций, поэтому `Uncovered: 0` в этом отчёте не означает полного покрытия. Итог 94,9% относится только к выборке. Исходный отчёт: [relay-mutation.edn](quality/relay-mutation.edn).

## Журнал исправлений, подтверждённых тестами

1. **Обход отзыва устройства.** Новый regression-тест получил 200 вместо ожидаемого 401: живой bearer token позволял повторно зарегистрировать отозванное устройство. Исправление отзывает связанную HTTP-сессию, все её устройства и WebSocket. Повторный тест прошёл; другой авторизованный клиент остаётся доступен.
2. **Миграция v1 → v3.** Первый общий набор показал 42/43: обновление старых сессий происходило раньше создания уникального индекса, необходимого внешнему ключу устройства. Индекс перенесён перед обновлением строк; отдельный тест старого аккаунта, пароля и сохранённых сессий прошёл.
3. **Пароль из одних пробелов.** Проверка нового пароля показала 201 вместо ожидаемого 400. Минимальное исправление отвергает пустое нормализованное значение; проверки намеренных внешних пробелов и 15 Unicode-кодовых точек остались положительными.
4. **Недопустимый `attachmentIds: null`.** Новый тест границ показал отсутствие ожидаемого отказа. Значение по умолчанию применяется только к отсутствующему полю; `null` и другие не-массивы получают 400. Повторная проверка прошла.
5. **Мутационная проверка границ.** Усилены реальные проверки разрешённых крайних значений и детерминированного порядка. После изменения тестов и устранения одной дублирующей проверки результат улучшился с 32/41 до 37/39 без изменения протокола.
6. **Финальная проверка.** На замороженных серверных исходниках выполнены 45/45 тестов и синтаксическая проверка; анализ Crapper использует именно полученное покрытие. Хеши серверных исходников сверены с копией, на которой запущены инструменты.

## Воспроизведение и доказательства

Финальный серверный запуск из папки `server`:

```sh
mkdir -p coverage
node --test --test-isolation=none --experimental-test-coverage \
  --test-reporter=spec --test-reporter-destination=stdout \
  --test-reporter=lcov --test-reporter-destination=coverage/lcov.info \
  test/*.test.js
npm run check
```

На отдельной копии проекта, с установленными зафиксированными версиями инструментов:

```sh
crapper --use-existing-coverage --threshold 9.999 --root ./server src
dryer --threshold 0.8 mobile/src mobile/App.tsx mobile/modules
mutator --root ./server --no-coverage --max-workers 2 \
  --lines 20,23,24,28,32,37,40,51,53,62,63,64,65,66,68 \
  --test-command "node --test --test-isolation=none --test-name-pattern='pure envelope boundary|device registration' test/e2ee-relay.test.js" \
  src/e2ee.js
```
