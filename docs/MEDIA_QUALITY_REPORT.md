# Проверка качества медиа 0.5.0

Это проверка ограниченного набора чистых парсеров, а не утверждение о качестве всего приложения. Проверяемые исходники побайтово сравнивались с изолированными staging-копиями; SHA-256 — `media-quality/source-manifest.json`. Настоящие Crapper, Dryer и Mutator выполнялись, результаты не моделировались.

## PNG, HDR, EXIF orientation, JPEG

Четыре модуля: `png.ts`, `pngHdr.ts`, `exifOrientation.ts`, `jpeg.ts`. Итоговый Node-набор — **95/95**, точное покрытие строк и функций 100%, ветвей 98.92%. Вызовы тестов импортируют исходный TypeScript напрямую; LCOV не выдаёт строки transpiled VM за исходные.

Crapper: все функции ниже 10, максимум 9. Dryer при threshold 0.8 — 0 кандидатов. Mutator после добавления осмысленных граничных случаев: **300 killed, 5 survived, 0 uncovered из 305; 98.4%, exit 3**. Это не результат 100%.

Пять оставшихся мутаций JPEG разобраны как эквивалентные на уровне публичного контракта «допустимый JPEG либо отказ». Они меняют внутренние проверки уже неполного потока: segment header заканчивается на EOF, длина сегмента выходит за край, отсутствует обязательный EOI или дополнительная итерация проверяет EOF. Такие потоки всё равно отклоняются последующими обязательными проверками. Различие только в месте/причине отказа; тесты не привязывались к внутренней ветке ради процента. Точные места и операторы — `media-quality/photo-mutation-results/photo.jpeg.edn`.

Первые mutation-прогоны выявляли непроверенные настоящие границы HDR, диапазоны EXIF и валидности JPEG. Добавлены проверки соответствующих входов, упрощены избыточные условия, сохранён порядок обработки. Логи первого/второго/финального запусков включены отдельно. Независимый Pillow-декодер подтвердил одинаковые RGB-пиксели до/после очистки контрольного JPEG, размер 660→615 байт; это отдельный контрольный пример, не доказательство для всех JPEG.

## MP4

Три модуля: `mp4.ts`, `mp4Boxes.ts`, `mp4Samples.ts`. После приоритетного аудита — **26/26**. Проверены реальные границы sample tables, HDR/CICP, AAC descriptors, поля v0/v1, точное обнуление private boxes и промежутков mdat, сохранение разрешённых полей и сэмплов.

Crapper: 63 функции, все ниже 10, максимум 9.2983. Dryer при 0.8 — 0 кандидатов. Точное Node-покрытие строк: 99.74% для mp4.ts и 100% для остальных двух. После полного повторного Mutator: **431 killed, 93 survived, 0 uncovered из 524; 82.3%, exit 3**. Исторический первый результат — 362/160/2, 69.3%.

**Мутационный порог MP4 не пройден.** Уцелевшие изменения не объявлены все эквивалентными; среди них остаются недостаточно проверенные границы. В приоритетном повторном проходе по рискам приватности/повреждения данных добавлено 8 групп проверок. Они не выявили нового дефекта production-реализации, но это не исключает остальных дефектов. Не следует представлять код как прошедший полный независимый аудит.

Независимый FFmpeg verifier сравнил декодированные пиксели двух кадров, HDR side data, PCM на стадии очистки контейнера и отсутствие проверяемых приватных тегов. Два raw и три MP4 сценария прошли. Это representative fixtures, а не записи нативного выхода телефона. Нативный video path заново кодирует звук в AAC, поэтому lossless-аудио всей цепочки не заявляется.

## Нативный код и остальная система

Kotlin/Swift не поддерживаются использованными quality-командами в этих проектах. Их CRAP/DRY/mutation проценты не измерены. JVM фото —27/27, видео —13/13; Android модули компилировались. Нет Xcode-компиляции и выполнения media path на физических Android/iPhone.

AI/username/entitlement проверены отдельно, их результаты приведены в серверных отчётах; общий 100% mutation-gate всего приложения не достигнут. TSX, графический редактор, доступность, энергопотребление и реальные жесты требуют отдельной проверки. Web UI harness экспортируется, но получить скриншоты не удалось из-за явного browser URL policy block; обход не предпринимался.

Документ фиксирует результаты и ограничения предварительного выпуска. Он не отменяет пользовательское требование обязательного E2EE: открытые сообщения отклоняются независимо от качества медиа. Общие функциональные проверки и артефакт APK описаны в TEST_REPORT.md и BUILD_REPORT_0.5.md.
