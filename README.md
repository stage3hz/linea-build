# Линия 0.5.1 · Android/iPhone messenger

Разрабатываемый мессенджер с русским интерфейсом, собственным сервером, обязательным сквозным шифрованием личной переписки, музыкой и локальной обработкой медиа. React Native / Expo; «Линия» — рабочее название. Полный функциональный аналог Telegram пока не реализован.

Текущий состав обновления — [RELEASE_0.5.1.md](docs/RELEASE_0.5.1.md), фактически выполненные проверки — [PREPARATION_REPORT_0.5.1.md](docs/PREPARATION_REPORT_0.5.1.md). Добавлены бессрочная Platina, ограничения геолокации и доступа к другим приложениям, подготовка облачной iOS-сборки с управлением с iPhone. Инструкция — [BUILD.md](docs/BUILD.md).

**0.5.1 передаётся исходниками и серверным комплектом; нового APK или IPA нет.** Ранее собранный Android APK остаётся версией 0.5.0 и не содержит новых ограничений разрешений. Его подпись и SHA-256 описаны в историческом [BUILD_REPORT_0.5.md](docs/BUILD_REPORT_0.5.md), прежние тесты — в [TEST_REPORT.md](docs/TEST_REPORT.md). На физических телефонах обновление 0.5.1 не проверялось.

Группы, каналы, звонки, истории, боты, фоновый push и полный Telegram-паритет остаются следующими этапами: [TELEGRAM_PARITY.md](docs/TELEGRAM_PARITY.md).

### Ограничения обработки медиа

Максимальный очищенный файл — 20 МиБ, PNG/JPEG — до 16 Мп; конкретные режимы могут требовать уменьшения с явным разрешением. Удаление фона использует ML Kit на Android или Vision на iOS; доступность модели/версии ОС имеет значение. Видео ограничено AVC/HEVC; аудиодорожка перекодируется в AAC. HDR10+/Dolby Vision и неподдерживаемые пути отклоняются; Android KEY_HDR_STATIC_INFO сейчас также не переносится автоматически. Оригинал при ошибке не отправляется.

Содержимое пикселей, видимые надписи/лица и вся возможная стеганография не удаляются автоматически. Очистка метаданных не означает универсальную поддержку любого медиафайла. Полное описание — [MEDIA_0.5_REPORT.md](docs/MEDIA_0.5_REPORT.md), [PHOTO_NATIVE_0.5_REPORT.md](docs/PHOTO_NATIVE_0.5_REPORT.md), [VIDEO_NATIVE_REPORT.md](docs/VIDEO_NATIVE_REPORT.md).

## Вход и восстановление без почты и телефона

Регистрация состоит из четырёх шагов: ник, пароль, слово подтверждения и другое слово для восстановления. Каждое значение вводится дважды вручную. При обычном входе последовательно вводятся неизменяемый логин, пароль и слово подтверждения; проверка аккаунта выполняется после ввода всех трёх значений.

| Значение | Правила |
| --- | --- |
| Ник | 3–24 латинские буквы, цифры или `_`; регистр не различается. |
| Пароль нового аккаунта | 15–128 символов Unicode. Подходит длинная фраза. Регистр и намеренные пробелы учитываются. |
| Слово подтверждения | 4–64 русские или английские буквы без внутренних пробелов. Нужно при каждом входе. |
| Слово восстановления | Такие же правила длины и алфавита; должно отличаться от первого слова, ника и пароля. |

Для слов регистр не важен, внешние пробелы удаляются, применяется NFC; «е» и «ё» остаются разными буквами. Приложение не показывает сохранённые слова повторно. Пароль и оба слова на сервере представлены отдельными солёными хешами scrypt. Это три запомненных секрета одного типа, а не многофакторная авторизация.

Если пароль забыт:

1. Выберите **«Забыл пароль?»** и введите первоначальный логин со словом восстановления.
2. После правильного ответа сервер создаёт запрос и отсчитывает **10 минут**. Переустановка приложения или изменение часов телефона не сокращают серверное ожидание.
3. В действующих сеансах можно увидеть запрос и отменить его. Фонового push при закрытом приложении пока нет.
4. После окончания ожидания введите новый пароль дважды. На завершение есть **20 минут**; затем запрос истекает.
5. Все прежние сеансы отзываются. Войдите с новым паролем и прежним словом подтверждения: оба слова при восстановлении сохраняются.

Три неверные попытки блокируют только восстановление на 24 часа после третьей ошибки. Счётчик хранится на сервере, действует для аккаунта независимо от IP и переживает перезапуск. Обычный вход с паролем и словом подтверждения остаётся доступным. Правильная третья попытка принимается. Автоматического восстановления без слова восстановления в этом интерфейсе нет.

В **«Безопасности»** можно изменить пароль или слова, подтвердив текущий пароль и текущее слово входа. Такое изменение отзывает все прежние сеансы и незавершённые запросы восстановления. Старые аккаунты сохраняют прежний пароль; до настройки слова подтверждения его поле при входе можно оставить пустым, после входа приложение предлагает завершить настройку безопасности.

Короткое распространённое слово остаётся угадываемым даже при ограничении попыток. Десятиминутное ожидание даёт время отменить запрос из открытого сеанса и само по себе не доказывает личность. Проверки и границы утверждений — в [AUTH_TEST_REPORT.md](docs/AUTH_TEST_REPORT.md).

## Сквозное шифрование переписки

Для новых личных сообщений используется **официальный libsignal 0.106.0** через собственный нативный модуль Expo; обмен ключами и ratchet выполняет библиотека. Вложения шифруются на клиенте через AES-256-GCM-SIV из той же библиотеки. Сервер принимает шифротекст, публичные ключи и данные маршрутизации. Исходное имя файла, его ключ и содержимое передаются внутри зашифрованного сообщения.

Перед первым обменом откройте **«Защита чата»**, сравните коды пары устройств при встрече или через уже доверенный канал и подтвердите их. У двух участников для одной пары устройств код должен совпасть. Новое устройство требует новой проверки; сменившийся ключ не принимается автоматически. Без работающего нативного модуля или при ошибке проверки приложение не переходит к отправке открытого текста.

Закрытые ключи, состояние Signal, outbox и локальная история находятся в клиентском SQLCipher-хранилище; отдельный случайный ключ базы хранится через SecureStore и не выводится из пароля или коротких слов. Обновление состояния ratchet и сохранение исходящего пакета выполняются атомарно до отправки. Повтор использует прежний сохранённый шифротекст.

**Восстановление аккаунта и восстановление истории — разные операции.** Если прежнее локальное хранилище цело, новый пароль не уничтожает его ключи и историю. На новом устройстве или после потери ключей старые сообщения автоматически не открываются. Перенос ключей между устройствами и зашифрованная резервная копия истории в этой версии не реализованы. Поддерживается до пяти действующих устройств аккаунта; новые сообщения адресуются разрешённым устройствам.

Профили, аватары, участники чата, время и объёмы обмена не скрываются этим шифрованием. Старые открытые сообщения версии 0.2 не шифруются задним числом; сервер безусловно отклоняет открытый протокол и не выдаёт старый текст как защищённую переписку.

Результаты криптографических проверок базовой версии 0.5, включая Kotlin ↔ Node, реальный HTTP API, повреждение и повтор пакетов, приведены в [TEST_REPORT.md](docs/TEST_REPORT.md); более ранний отчёт — [E2EE_TEST_REPORT.md](docs/E2EE_TEST_REPORT.md). Изменения и повторные проверки 0.5.1 перечислены отдельно в [PREPARATION_REPORT_0.5.1.md](docs/PREPARATION_REPORT_0.5.1.md). Это не независимый аудит. У libsignal лицензия AGPL-3.0-only; соблюдение её условий требуется при распространении.

Политика только E2EE и условия будущих звонков: [E2EE_ONLY_0.5.md](docs/E2EE_ONLY_0.5.md). **Звонки пока отсутствуют.** Вкладка AI отдельно передаёт введённый туда запрос внешнему провайдеру только по согласию; она не получает личные переписки автоматически и не называется E2EE-разговором между людьми.

## Музыка: быстрый запуск

1. Откройте приложение и нажмите **«Музыка»** вверху экрана подключения/входа. Сервер «Линии» и регистрация для этого не нужны. В открытом аккаунте музыкальная вкладка находится в нижней панели списка чатов.
2. Введите название или исполнителя либо выберите настроение. Поиск идёт по реальному каталогу Audius; настроения используют метки треков, а не персональную рекомендательную модель Яндекса.
3. Нажмите трек. Нижний мини-плеер продолжает управлять музыкой при переходе к другим экранам; нажатие на него открывает обложку, перемотку, очередь и дополнительные действия.
4. **«Можно скачать»** включён по умолчанию. Для более широкой выдачи отключите его. Загрузка доступна через меню трека или плеер: **«Скачать через Audius»** открывает официальный адрес в браузере после повторной проверки разрешения.
5. Для своей офлайн-библиотеки нажмите **«+»**, выберите аудиофайлы на устройстве и откройте **«Мои файлы»**. На Android/iPhone приложение хранит собственную копию; удаление из приложения не удаляет исходный файл. В web-представлении импорт временный, до перезагрузки или выхода.

Линия не вставляет рекламу, не требует музыкальной подписки и не вводит лимита переключений треков. Это **публичная часть каталога Audius**, доступная сторонним плеерам; Яндекс Музыка и SoundCloud в эту версию не подключены. Наличие всех песен, неизменность каталога, доступ из каждой страны, lossless для каждого трека или право скачать любой трек не гарантируются. Качество онлайн-аудио определяется ответом источника; собственные файлы не перекодируются приложением, поддержка форматов зависит от ОС.

Автор может закрыть доступ API, сделать трек платным или разрешить скачивание только определённой аудитории. Такие ограничения проверяются при поиске и заново перед воспроизведением/загрузкой. Поисковый фильтр сам по себе разрешением не считается. См. [официальные настройки релиза Audius](https://help.audius.co/product/editing-your-release).

Постоянного офлайн-кэша потоков Audius в приложении нет: [API Terms](https://audius.co/documents/ApiTerms.pdf) допускают сессионный кэш. Избранное Audius хранит на устройстве только ID; сведения о треках загружаются заново. Собственные файлы и избранное относятся к устройству, не синхронизируются с сервером чатов и остаются доступными при смене аккаунта на этом устройстве. При выходе или смене сервера плеер останавливается.

Поиск, обложки и воспроизведение обращаются к Audius и его узлам; источник видит запросы и сетевые данные соединения согласно [Privacy Policy](https://audius.co/documents/PrivacyPolicy.pdf). Пароль и токен «Линии» туда не передаются. Импортированные файлы на сервер не отправляются. В разделе «О музыке» доступны условия API, конфиденциальность и [Open Music License](https://audius.org/open-music-license.pdf).

Собственные файлы: до 250 МиБ на файл, до 500 записей в локальной библиотеке; требуется свободное место. Операции импорта, системное меню сохранения и фоновое воспроизведение на физическом телефоне ещё требуют проверки. Настройки фонового аудио и управления на экране блокировки включены в сборку, но не заявляются испытанными на устройстве. Детали — [MUSIC_TEST_REPORT.md](docs/MUSIC_TEST_REPORT.md).

## Подключение нативного приложения к серверу

Для настройки VPS с iPhone подготовлены отдельный серверный архив `linea-server-v0.5.1.zip` и [пошаговая инструкция](docs/DEPLOY_FROM_IPHONE.md). Для сборки и установки на iPhone без собственного Mac — [инструкция облачной сборки](tools/ios-cloud-setup/README.md); в полном исходном комплекте уже включены необходимые инструменты. Нужны собственный Expo-проект и действующие права на Apple-подпись для этого устройства.

Готовый APK содержит JavaScript и ресурсы, Metro ему не нужен. Expo Go не содержит LineaSignal/LineaPhoto/LineaVideo и SQLCipher, поэтому для исходного клиента нужна нативная сборка.

1. Разверните собственный API за HTTPS: [DEPLOYMENT.md](docs/DEPLOYMENT.md). Конфигурация поддерживает два принадлежащих вам домена .ru/.com с одной базой. Реальные домены/сервер здесь не создавались.
2. Установите APK и введите свой HTTPS-адрес с действующим сертификатом. Локальный `http://LAN-IP:3001` готовая release/preview-сборка отклоняет; отдельная dev-настройка описана в BUILD.md.
3. На втором телефоне подключитесь к тому же серверу, зарегистрируйте второй аккаунт, найдите его по @username, сравните и подтвердите коды устройств в «Защите чата».
4. Отправьте сообщение/вложение. Отсутствие одобренных ключей блокирует отправку.

На сервере нужны Node.js 24 и зависимости: `npm --prefix server ci`, затем `npm run server`. Порт 3001 предназначен для внутреннего API; внешний доступ — через HTTPS reverse proxy. Музыка доступна без аккаунта/сервера Линии.

Изменение `.env.local` не меняет установленный APK. В приложении адрес выбирается на экране подключения; `EXPO_PUBLIC_API_URL` лишь задаёт начальный адрес при сборке. Секреты, включая OPENROUTER_API_KEY, нельзя включать в EXPO_PUBLIC-переменные.

## Автоматическая тема и стеклянное оформление

При первом запуске выбран режим **«Как в системе»**. Светлая ОС выбирает светлую палитру; для тёмной ОС пользователь выбирает navy или black. Ручной режим — светлый, тёмно-синий или чёрный — сохраняется и имеет приоритет над ОС. Black имеет базу #000000 и полупрозрачные чёрные поверхности; прозрачность смешивается с фоном. Реализация и проверки — [PROFILE_THEME_UI_REPORT.md](docs/PROFILE_THEME_UI_REPORT.md).

Стеклянные панели реализованы в [`mobile/src/glass.tsx`](mobile/src/glass.tsx): более плотный материал `regular` используется для форм и читаемого содержимого, более прозрачный `clear` — для элементов навигации. Сообщения используют лёгкие полупрозрачные заливки и границы без отдельного blur на каждой реплике.

| Платформа | Реализация материалов |
| --- | --- |
| iOS 26 и новее | Нативный `GlassView` при положительных проверках доступности; выбранная тема передаётся явно |
| Более ранняя iOS / недоступный GlassEffect | Blur и цветовые слои вместо недоступного нативного стекла |
| Android 12 и новее | Нативный blur через `BlurTargetView`; target содержит только декоративный фон |
| Более ранний Android | Полупрозрачные слои и границы без blur |
| Уменьшение прозрачности | На iOS учитывается системная настройка и её изменения; на web — поддерживаемый браузером media query. Применяется плотная заливка |

Платформенные возможности описаны в официальной документации [Expo GlassEffect SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/glass-effect/) и [Expo BlurView SDK 57](https://docs.expo.dev/versions/v57.0.0/sdk/blur-view/). Конкретный внешний вид на физических телефонах требует проверки на этих устройствах.

[Glass-HQ/liquid-glass](https://github.com/Glass-HQ/liquid-glass) использован как визуальный ориентир. Репозиторий предназначен для web/Electron и WebGPU; его библиотека в React Native не портировалась. Android-реализация размывает декоративный фон, а WebGPU-рефракцию живого содержимого из референса не воспроизводит.

## Запуск исходного клиента для разработки

После `npm run setup` оставьте `npm run server` работающим в первом терминале. Соберите нативный клиент с Android SDK или Xcode:

```bash
npm --prefix mobile run android
# На macOS с настроенным Xcode:
npm --prefix mobile run ios
```

Требуются зависимости и параметры из [BUILD.md](docs/BUILD.md), включая нативный Signal и SQLCipher. Для последующих JavaScript-изменений в уже собранном development-клиенте запускайте `npm run mobile`; изменение нативных зависимостей требует пересборки. См. [официальное руководство по development builds](https://docs.expo.dev/develop/development-builds/introduction/) и [SQLCipher в Expo SQLite](https://docs.expo.dev/versions/v57.0.0/sdk/sqlite/).

Для проверки авторизации и музыки в браузере есть `npm run web`. Этот режим не включает зашифрованный чат.

`setup` создаёт `mobile/.env.local` с `EXPO_PUBLIC_API_URL`, если находит локальный IPv4 и файла ещё нет. Существующий файл не перезаписывается. При смене сети исправьте адрес и перезапустите Expo командой `npm --prefix mobile start -- --clear`. Для интернет-сервера используйте HTTPS.

## Хранение и ограничения

По умолчанию база находится в `server/data/linea.sqlite`, вложения — в `server/data/uploads/`. Не удаляйте этот каталог при обновлении. Для согласованной резервной копии остановите сервер и скопируйте весь `server/data`.

Пароли сохраняются как salted scrypt, в базе хранится хеш токена сессии. На Android/iOS токен клиента сохраняется через Expo SecureStore; временный web-клиент использует sessionStorage. Источники: `server/src/security.js`, `server/src/app.js`, `mobile/src/storage.ts`. Это свойства реализации, а не заключение независимого аудита.

Серверная резервная копия сохраняет аккаунты и зашифрованные пакеты, но не заменяет клиентские закрытые ключи. В этой версии нет групп, каналов, звонков, фоновых push, удаления аккаунта и редактирования/удаления сообщений. Системные уведомления при закрытом приложении не настроены. Полный функционал Telegram ещё не реализован.

Файл — до 20 МиБ (`20 × 1024 × 1024` байт), аватар — до 4 МиБ, квота файлов по умолчанию — 512 МиБ на аккаунт. Сессия по умолчанию действует 30 дней. Источники значений и настройки: [`server/README.server.md`](server/README.server.md).

Сервер использует один процесс, SQLite и файловое хранилище. Массовая нагрузка и отказоустойчивость не проверялись. Перенос в несколько процессов требует общего хранилища ограничителей запросов; постоянный бюджет восстановления уже находится в SQLite. Отчёт проверки зависимостей базовой версии приведён в [TEST_REPORT.md](docs/TEST_REPORT.md); в 0.5.1 состав зависимостей не менялся.

Схема 5 добавляет бессрочные выдачи Platina. До первого запуска сервера 0.5.1 на прежней базе сделайте полную согласованную резервную копию. После миграции сервер 0.5.0 не откроет эту базу. Порядок выдачи и отката — [PLATINA_OWNER_0.5.1.md](docs/PLATINA_OWNER_0.5.1.md).

## Проверка проекта

```bash
npm run check
```

Базовая команда проверяет сервер, музыку, ручной ввод, даты, фото/медиа, AI, вложения, темы/статусы, HTTPS и типы клиента. E2EE-проверки требуют отдельно установленного закреплённого Node SDK; межъязыковая проверка дополнительно требует JDK 21 и собранного JVM-драйвера. Полные инструкции — в [E2EE_TEST_REPORT.md](docs/E2EE_TEST_REPORT.md). Дополнительные команды:

```bash
npm --prefix server run check
npm --prefix server test
npm --prefix mobile run typecheck
npm --prefix mobile run test:music
node --test --test-isolation=none mobile/test/manual-entry.test.mjs
node --test --test-isolation=none mobile/test/e2ee*.mjs
cd mobile
npx expo install --check
npx expo export --platform all
```

Экспорт JavaScript и ресурсов не заменяет нативную компиляцию и запуск на устройстве. Фактически подтверждённые результаты отдельно указаны в `docs/TEST_REPORT.md`.

## Сервер в контейнере

Для локального запуска подготовлен `compose.yaml`:

```bash
docker compose up --build -d
```

API использует порт 3001, данные — именованный том. Docker-команда дана как инструкция: контейнерная сборка в среде подготовки отдельно не проверялась.

Для размещения в интернете нужен HTTPS reverse proxy с WebSocket. Browser Origin и доверенные proxy настраиваются через `server/.env.example`. Android React Native автоматически отправляет Origin адреса WS; сервер принимает его в узком исключении с обязательной авторизацией. Точные правила описаны в `docs/API.md`. При proxy сохраняйте внешний `Host`.
