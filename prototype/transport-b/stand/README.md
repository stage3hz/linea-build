# Подготовка отдельного стенда

Эти инструменты не устанавливаются на действующий сервер INVIZENT.
`194.87.254.249` обслуживает рабочий API; владелец это подтвердил.
Они не обходят сетевые ограничения среды Codex и не запускают удалённый shell.

## Проверка и сборка файлов

`prepare.py` требует Ubuntu 24.04 x86_64, Python 3.12, `ip`, `ss`; для сборки нужен
Git. По умолчанию выполняется только чтение:

```sh
python3 -B prepare.py --check
```

Коды `KNOWN_PRODUCTION_HOST`, `CANONICAL_API_HOST`, `RUNNING_DOCKER_CONTAINERS`
и `RESERVED_SERVICE_LISTENER` запрещают подготовку. Неполная инвентаризация,
неработающий DNS и другой публичный listener также приводят к отказу.
Не предусмотрено флага для обхода проверок. Они видят текущие namespaces и не
заменяют подтверждение владельца: за NAT роль машины может быть скрыта.

На подтверждённом отдельном пустом сервере явный запуск:

```sh
python3 -B prepare.py --prepare /opt/invizent-stage-b-stand
```

Создаётся новый приватный каталог; существующие каталоги не перезаписываются.
В него загружается Go 1.26.1 с проверкой фиксированного SHA-256, исходники
закреплённого upstream, последовательно собираются Telemost Creator и Joiner.
Проверяется их `--help`, сохраняются бинарники, лицензия и manifest с хешами.
Кэш официального Go-архива можно передать через `--go-archive /absolute/file`;
его хеш проверяется так же строго. Git/Go не получают произвольные секреты
приложения из окружения. Go memory limit — мягкий предел, не гарантия cgroup.

Ничего не добавляется в автозапуск, не создаются комнаты, аккаунты, cookies,
сетевые слушатели, namespace/firewall или HTTP bootstrap. `manifest.json`
прямо отмечает `platform_connection_verified: false`.

## Приватный вход владельца

`browser-session.mjs` — вспомогательный экспорт из видимого официального Chrome.
Он требует уже подготовленные локальные DISPLAY/XAUTHORITY, непривилегированного
пользователя, Node 18+ и доверенный root-owned Chrome. Пример интерфейса:

```sh
node browser-session.mjs --chrome /usr/bin/google-chrome \
  --profile /absolute/NEW/private-profile \
  --output /absolute/NEW/private-session/cookies-yandex.json
```

Владелец сам входит на официальной странице Телемоста/Яндекса. Управление Chrome
использует анонимные CDP pipes; debugging/VNC TCP-порт не открывается, sandbox
не отключается. Подходящая Яндекс-сессия сохраняется исключительно в новом файле
0600 внутри каталога 0700, вне Git. Значения cookies, имя аккаунта и сырые ошибки
браузера в терминал не выводятся. Есть отмена и срок 15 минут; профиль остаётся
приватным. Пароли, OTP, cookies и профиль не передаются в чат или CI artifacts.

**Подготовка реального графического сеанса/VNC провайдера не автоматизирована.**
Этот helper не создаёт display и не доказывает доступность Яндекса с VPS.
Установка GUI и личный вход требуют отдельного разрешённого стенда. На рабочем
VPS запускать их нельзя под прежней областью задачи.

## Доказательства и пределы

- Unit-тесты проверяют отказ на рабочем хосте до записи, неизвестную инвентаризацию,
  права и отсутствие перезаписи, CDP framing/очереди/отмену, фильтр cookies и
  отсутствие секретных диагностик.
- `Dockerfile.proof` создаёт одноразовую пустую Ubuntu. В ней проверяется настоящая
  сборка Go; `verify-manifest.py` независимо сверяет архив и бинарные файлы/хеши,
  ELF x86_64, справку и права. Это не независимая повторная сборка.
- `browser-proof.mjs` использует настоящий видимый Chrome в Xvfb, анонимные pipes
  и синтетическую cookie. Страницы Яндекса не открываются, входа в аккаунт нет.
  Это проверяет CDP/export, не полный CLI/установку GUI/гипервизорную консоль.
- CI: `stage-b-stand-proof.yml`. Ни один из этих результатов не подтверждает
  реальный Creator ↔ Joiner, работу iPhone/оператора, сетевую изоляцию или готовность
  пользовательской версии резерва.
