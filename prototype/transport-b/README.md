# Этап B — экспериментальный резервный транспорт INVIZENT

**Только прототип. В production не включено.** Нет реального подключения через WB Stream/Телемост/VK, нет развёрнутого сервера, нет готового iOS/Android-модуля, нет подтверждения работы при ограничениях конкретного оператора.

## Что готово в этой ветке

- Основа — ветка auto-connect-a, коммит 3f461cb. Ветка Клода не менялась, main не менялся.
- Исправлена небезопасная повторная отправка записей после 502/503/504: сама ошибка шлюза не доказывает, что операция не выполнилась.
- При смене HTTPS-адреса WebSocket сообщений теперь переоткрывается на новом адресе.
- Отдельный экспериментальный модуль prototype/transport-b/src/creator-pool.mjs управляет процессами headless WB Stream: одна сессия на устройство, лимиты процессов, освобождение, таймауты, отсутствие логирования секретных ссылок.
- Десять локальных тестов этого менеджера прошли на Node 22. Они используют поддельный дочерний процесс, реального подключения не делают.
- Добавлен чистый клиентский валидатор mobile/src/network/transportB/lease.ts для краткоживущей Ed25519-подписанной ссылки, привязанной к конкретному устройству и нашему realm. Приём ссылки в сетевом коде пока не подключён; конфигурация ключа подписи и доставка lease остаются отдельной задачей.
- Тесты мобильного валидатора: mobile/test/transport-b-lease.test.mjs. Подпись, срок, устройство, последовательность и URL проверяются без обращения к видеоплатформе.

Команда запуска тестов из корня репозитория:

    node --test prototype/transport-b/test/*.test.mjs

## Почему это пока нельзя выкатывать

Рассмотрен сторонний открытый проект kulikov0/whitelist-bypass (MIT), где headless creator создаёт WebRTC-сессию, а joiner подключается через VK, Яндекс Телемост, WB Stream и другие сервисы. Важное ограничение разработчиков: **один Creator обслуживает ровно одного Joiner**. Одну общую ссылку для всех клиентов использовать нельзя.

Creator — потенциальный прокси общего назначения. В прототипе обязательно указан локальный upstream SOCKS, но **это ещё не означает, что сетевая изоляция гарантирована**. Перед развёртыванием нужны отдельный контейнер/namespace, правила исходящего доступа только к нашим сервисам, запрет обходного прямого выхода, защита от доступа в внутреннюю сеть и проверка от открытого прокси. Секреты сторонней платформы должны оставаться на сервере.

Сейчас этот модуль **не имеет HTTP API и не подключён к production Fastify**. Он не получает токены пользователей и не просит пароли.

## Что требуется для завершения этапа B

1. На изолированном стенде подтвердить, что реальный headless creator и joiner соединяются, что выбранный сервис действительно доступен в нужной сети, что это соответствует правилам сервиса и что данные проходят в обе стороны.
2. Подготовить подписываемые, проверенные нативные библиотеки iOS (.xcframework) и Android (.aar) и обёртку Expo с событиями состояния и остановкой. Протестировать на физических телефонах. Не полагаться на Expo Go.
3. Добавить **app-scoped** передачу только трафика INVIZENT. Локальный SOCKS5 сам по себе не заставляет React Native fetch, WebSocket, image loaders и native uploads использовать туннель: нужен нативный маршрут. TLS, сертификаты, аутентификацию и E2EE сохранять.
4. Сделать безопасный механизм выдачи каждой клиентской сессии и её отзыва. Главная нерешённая проблема: **если основной API недоступен уже при первом запуске, нельзя получать параметр подключения исключительно с этого API**. Нужен отдельный проверенный bootstrap через реально доступный путь и без общих постоянных ссылок.
5. Настроить лимиты VPS и квоты: 4 vCPU / 8 ГБ RAM / 50 ГБ диска известны, но текущая нагрузка не измерена. Два процесса — предохранитель для эксперимента, не расчёт массовой ёмкости.
6. Проверить не только текст, но и вложения, WebSocket, переключение Wi-Fi ↔ LTE, выход в фон, звонки и уведомления. Push iPhone при блокировке APNs туннелем внутри приложения не восстанавливается автоматически.
7. Испытать на **реальном ограниченном мобильном интернете**. Эмуляция локальной потери связи проверяет корректность логики, но не результат на конкретной сети.

## Definition of done

Основной маршрут недоступен; INVIZENT на iPhone/Android без ручного VPN и без настройки пользователем устанавливает собственное защищённое резервное соединение; сообщения проходят в обе стороны, без повторного входа, потерь и дублей. Результат подтверждён измерениями на реальной сети. Не обещать работу при любых режимах фильтрации.
