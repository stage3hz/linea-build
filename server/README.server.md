# Сервер Линии 0.5.1

Один процесс Node.js 24 + Fastify + WebSocket + SQLite. Сервер обслуживает аккаунты без почты/номера, отдельные слова для входа и восстановления, личные чаты и передачу зашифрованных сообщений/файлов. Приватные Signal-ключи и ключи файлов на сервер не загружаются. Сервер видит метаданные, публичные профили и принимает секреты входа по HTTPS для проверки хешей.

## Локальный запуск

Для размещения с телефона следуйте [инструкции для iPhone](../docs/DEPLOY_FROM_IPHONE.md). Следующие команды предназначены для локального Node.js 24, из каталога, в котором находится папка `server/`:

```bash
npm --prefix server ci
npm --prefix server start
```

По умолчанию порт 3001. Проверка: `http://localhost:3001/health`. Для телефона localhost означает телефон; укажите LAN-IP компьютера либо production HTTPS-домен. Компьютер и сервер должны оставаться включёнными. Готовый APK принимает только HTTPS. HTTP для одноразовых локальных тестов включается только в dev runtime явным EXPO_PUBLIC_ALLOW_LOCAL_HTTP=1; распространение — за HTTPS reverse proxy.

`server/.env.example` описывает HOST, PORT, DATA_DIR, LOG_LEVEL, ALLOWED_ORIGINS, TRUSTED_PROXIES, SESSION_TTL_DAYS, AUTH_RATE_LIMIT и USER_STORAGE_MIB. Скопируйте его в `server/.env` и настройте при необходимости. Native-клиенту не нужен HTTP CORS; web origins разрешаются точно, без wildcard. Доверенные прокси — только реальные адреса proxy, иначе подмена IP разрушит ограничение попыток.

## Схема и обновление

Schema version 5 поддерживает прежнюю авторизацию, recovery grants/attempts, устройства шифрования, prekeys/tombstones и encrypted JSON сообщений. Переход 4 → 5 допускает NULL в сроке административной выдачи Platina, сохраняя прежние конечные выдачи, отзывы и audit. Сервер 0.5.0 после этого не откроет базу; для отката нужна согласованная копия схемы 4. [Выдача бессрочной Platina и миграция](../docs/PLATINA_OWNER_0.5.1.md). Перед обновлением остановите API и сделайте полную копию DATA_DIR. Старые сообщения остаются в БД; новые production ответы скрывают их plaintext и помечают legacy. Это не ретроактивное шифрование архива.

Аккаунты старых версий сначала входят со старым паролем и пустым подтверждением; клиент предлагает настроить два слова. Новые аккаунты обязаны иметь оба слова. Восстановление меняет только пароль и отзывает все сессии. Старый локальный vault остаётся на прежнем устройстве; на новый телефон сервер его не восстанавливает.

## Файлы и ресурсы

Аватары — проверенные изображения до 4 MiB. Новые чат-вложения — ciphertext до 20 MiB +64 bytes. Неприкреплённые blobs доступны владельцу; прикреплённые — участникам чата. Квота USER_STORAGE_MIB действует на аккаунт. Нужен отдельный мониторинг свободного места; квота не резервирует физический диск заранее.

База, WAL и uploads находятся в DATA_DIR. Используйте один API-процесс с этим SQLite; горизонтальное масштабирование требует другого общего слоя хранения и событий. Подробные HTTP/WS-контракты — `../docs/API.md`.

## Production и копии

Готовые конфигурации находятся в `../deploy`, инструкция — `../docs/DEPLOYMENT.md`. Caddy обслуживает два домена .ru/.com с одной БД; сам API не публикует внешний порт. Реальные VPS, DNS и выпуск TLS-сертификатов в этой среде не выполнялись.

`deploy/backup.sh` кратковременно останавливает API и копирует весь data volume. Нужно хранить зашифрованные копии отдельно от VPS и проверить восстановление на тестовом сервере. Резервная копия сервера не содержит приватных ключей телефонов и не заменяет их резервирование. Перенос клиентской истории пока не реализован.

## Проверка

```bash
npm --prefix server run check
```

Полный набор тестов находится в `linea-messenger-v0.5.1.zip`. Небольшой серверный архив `linea-server-v0.5.1.zip` содержит только файлы для размещения; каталога `server/test` в нём нет. Из полного исходного комплекта:

```bash
npm --prefix server test
```

Runner использует Node 24 `--test-isolation=none`; тесты с WebSocket требуют разрешённого локального bind. Все данные тестов создаются во временных каталогах. Старый открытый режим удалён, включая конструктор приложения. Все транспортные регрессии используют E2EE-конверты; настоящая криптография проверяется отдельными клиентскими тестами.

Полный серверный набор 0.5.1: 93/93 PASS; отчёт текущего обновления — `../docs/PREPARATION_REPORT_0.5.1.md`, подробности Platina — [PLATINA_OWNER_0.5.1.md](../docs/PLATINA_OWNER_0.5.1.md). Исторические итоги базовых версий находятся в документах полного исходного комплекта: `../docs/TEST_REPORT.md`, `AUTH_TEST_REPORT.md`, `E2EE_TEST_REPORT.md`, `QUALITY_REPORT.md`. Нет независимого аудита, нагрузочных испытаний, фоновых APNS/FCM, групп, каналов или звонков. Отдельно проверьте настоящие Android/iPhone клиенты, внешний HTTPS и восстановление копии перед пользовательским запуском.


## Дополнения 0.5

Неподвижный логин, одна бесплатная смена публичного @username, серверные права Platina и статусы описаны в `../docs/API.md`. Серверный ключ OPENROUTER_API_KEY включает необязательный текстовый AI; клиентских AI-ключей нет. Платежи, звонки, группы и каналы пока отсутствуют. Входящие запросы AI — отдельная внешняя обработка по согласию, не личные E2EE-переписки. Строгая политика сообщений и будущих звонков: `../docs/E2EE_ONLY_0.5.md`.
